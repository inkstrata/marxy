# MARXY-130 — Give the corpus a real document of every format marxy is for

**Design:** [10-gates-and-testing](../../design/10-gates-and-testing.md) §Writing a test an implementor cannot get wrong · **Review:** [2026-09-review-1](../../taste-review/2026-09-review-1/decisions.md) (MARXY-64 follow-up) · **Depends on:** MARXY-64, MARXY-75.

**Outcome.** Every typesetting and aesthetics judgement is currently made on continuous prose and a
README. `AGENTS.md` puts the content types in priority order — READMEs, AI and agent artifacts, source
files, prose — and the corpus is thin on three of the four. Four real documents fix the sample, and
every gate that walks the corpus starts covering them for free.

## Files and signatures
- `fixtures/corpus/16-api-reference.md` — deep nested lists, option tables, many inline code spans.
- `fixtures/corpus/17-changelog.md` — version headings, dense short bullets, links, dates.
- `fixtures/corpus/18-agent-transcript.md` — interleaved prose, tool output, fenced blocks with
  different languages, long unbroken paths.
- `fixtures/corpus/19-source-file.md` — a source file read as a code document: one long fence, lines past
  120 characters. (If 16–19 are taken, take the next four free numbers and say so in the PR.)
- `packages/core/goldens/` — the AST and HTML goldens for the four, regenerated by the existing script.
- `docs/taste-review/2026-09-marxy-130/` — each document rendered dark, 960 px, 2×.

## Do this, in order
1. Write the four documents. They are bytes: real content a reader could plausibly open, written by
   hand, never produced from the parser or from a template loop.
2. Regenerate the goldens with the committed script; read the diff and say per file what it shows
   (heading depth, table count, code-block count).
3. `node scripts/measure-parse.mjs` before and after, both outputs in the PR.
4. `pnpm test`, `pnpm gate:no-network`, `pnpm gate:fidelity`, then the artifacts and one queue row
   asking whether each document reads as its own format.
5. `pnpm done MARXY-130`.

## Tests → expected
| Check | Expect |
| --- | --- |
| `git diff --name-status origin/main...HEAD -- fixtures/` | only `A` lines; no existing fixture byte changes |

| `measure-parse.mjs` | both runs recorded; the cost of the wider corpus is stated, not discovered |

## Acceptance → check
The seven criteria on the CSV row.

## Do not
Modify a byte of an existing fixture. Generate a fixture at test time. Add a document that references a
remote image or any URL that would be fetched. Touch a gate script, a budget file or anything under
`apps/` or `packages/` other than the goldens. Add a fifth format because it is easy: four is the
sample the review asked for.
