# MARXY-16 — Ship v0.0.1 on macOS and Linux from a tag

**Design:** [06-shell](../../design/06-shell.md) (bundle config) · **Depends on:** MARXY-13, MARXY-15, MARXY-5.

## Outcome
`git tag v0.0.1 && git push --tags` produces a GitHub pre-release with a `.dmg`, an `.AppImage` and a `.deb`; each installs and opens `02-readme-real-world.md`.

## Do this, in order
1. `apps/desktop/src-tauri/tauri.conf.json`: `bundle.targets = ["dmg", "appimage", "deb"]`, `bundle.icon` includes an `.icns` and a `.ico` generated by `pnpm tauri icon icons/icon.png` (commit the outputs; they are binary, `.gitattributes` already marks `*.png`; add `*.icns *.ico binary`).
2. `.github/workflows/release.yml`: verify the macOS job passes `--target aarch64-apple-darwin` and that signing env is optional (already gated); add a post-build step that uploads `results/` and runs `pnpm gate:bundle` against the produced bundle sizes; on Linux install `libfuse2` for AppImage tooling if the runner lacks it.
3. Add `scripts/verify-release.mjs`: given the release assets, checks sizes against `fixtures/perf-budgets.json` and that each archive contains the binary; run it in the workflow.
4. Tag from `main` only after CI is green; if the workflow fails, fix and re-tag `v0.0.1` only if the failed tag never produced a release, else `v0.0.2`.

## Acceptance → check
Release exists with three assets → workflow run URL in the PR; `verify-release.mjs` output attached; a human confirms launch on each platform (`needs-human.md` entry: "install v0.0.1 on a Mac and on Ubuntu 24.04, open the README fixture, report").

## Do not
Store any secret in the repo. Change the app's behaviour.
