# Clipboard rules: Settings › Clipboard and the Privacy page

**Verdict:** change (mock row 14: the rules sheet becomes settings rows). **Decided by:**
[ADR-0066](../../../adr/0066-clipboard-history.md), proposed. **Built by:** J-08 (the keys and the
files) and J-10 (the rows and the lines) in [08-cards-studio.md](../08-cards-studio.md), on W-12's
settings view. **Plate:** [rules.html](rules.html).

**In short.** Four keys in `config.toml` govern history. Settings › Clipboard shows them as rows,
written only where they differ from the default, as every setting is (W-12). The Privacy page carries
one sentence for history, verbatim from ADR-0066, and the path where `keep` puts the files.

## The keys

| Key | Values | Default | Row in Settings › Clipboard |
| --- | --- | --- | --- |
| `clipboard_history` | `"off"`, `"session"`, `"keep"` | `"session"` | *Clipboard history*: Off / This session / Keep between launches (a segmented control) |
| `clipboard_keep_items` | 10 to 5,000 | 500 in `keep`, 200 in `session` | *Keep at most*: a number of unpinned copies. The value the reader sets applies in both modes; only the defaults differ |
| `clipboard_keep_days` | 0 to 365 (0 is no limit) | 30 | *Remove unpinned copies after*: days; disabled with a reason unless `keep` |
| `clipboard_skip_secrets` | `true`, `false` | `true` | *Skip text that looks like a secret* |

Top-level keys, so the existing `setTopLevelKey` writes each one without touching another byte
(`docs/design/11-config-and-storage.md`). An invalid value falls back to the default with a notice, as
every key does. The section also holds J-04's *Default copy format* and two buttons: *Clear
unpinned…* and *Clear everything…*, each with its count and a confirmation.

**Changing the mode.**

- `session` → `keep`: "Also keep the 14 copies from this session?" (*Keep them* / *Start empty*).
- `keep` → `session` or `off`: "Delete the 212 kept copies from this Mac?" (*Delete* / *Cancel*);
  *Delete* removes `clipboard/`, *Cancel* leaves the setting as it was.
- `session` → `off`: the in-memory history is dropped, without a question (nothing was on disk).

## The Privacy page

W-12's Privacy page is "a computed list of everything that can leave the machine", and what Marxy
keeps. While `clipboard_history` is not `off`, it shows the constant `CLIPBOARD_HISTORY_PRIVACY_LINE`,
verbatim from ADR-0066 item 8:

> Marxy keeps what you copy in Marxy, and what you ask it to keep, on this Mac, in memory until you
> quit or, if you choose to keep history between launches, as plain files in Marxy's data folder. It
> reads what other apps copy only when you paste or ask it to, and sends nothing anywhere.

Under it, in `keep`, the folder (`~/Library/Application Support/marxy/clipboard/`, or
`$XDG_DATA_HOME/marxy/clipboard/` on Linux), its size, *Reveal* and *Clear everything…*. A test reads
the sentence out of the ADR, as P-02's test reads ADR-0063's.

## What is never recorded

| Never recorded | Because | Under |
| --- | --- | --- |
| Marxy's temporary writes, marked `org.nspasteboard.TransientType` | They are not the reader's copy | A |
| A concealed item (`org.nspasteboard.ConcealedType`) | J-01 refuses to read it, so its data is never seen | A (every read), B |
| A transient or auto-generated item read from the clipboard (`TransientType`, `AutoGeneratedType`) | Not the reader's copy; refused after the types, before any data (default pending the author) | A (every read), B |
| Text that looks like a secret | The table in ADR-0066 item 7 (AWS, GitHub, GitLab, Slack, Stripe, OpenAI-style and Anthropic-style keys, PEM private keys, JWTs, `.env` lines with a secret-like key); a match anywhere refuses the whole item, in memory, before anything is stored (`clipboard_skip_secrets`) | A, B |
| Text over 1 MB | It still works as the clipboard; it is not stored | A, B |
| Images and file references | Not designed yet (later) | A, B |
| Anything while paused or off | The reader said so | A, B |
| An item from an excluded app | The reader's list, by bundle id | B |
| The text of a *not recorded* row | Only source, reason and time, in memory | A, B |

## The files

Only in `keep`, in Marxy's data directory, plain files (ADR-0066 item 5):

```
clipboard/index.json        {"version": 1, "items": [{"id": "20261010T142233-3f9a", "at": "…",
                              "bytes": 412, "format": "slack", "origin": "copy", "pinned": false,
                              "source": {"path": "~/Dev/marxy/docs/plan.md", "start": 1204,
                              "end": 1616, "line": 42}, "reps": ["text"]}]}
clipboard/items/<id>.txt    the text as written
clipboard/items/<id>.html   the HTML, when the copy had one
```

The reader may open, grep, copy or delete any of them; Marxy reconciles at launch (an item file the
index does not name is deleted, an index entry with no file is dropped). Nothing else about history is
written anywhere: not in `history.json` (the opens and pins file, a different file), not in `positions.json`, not in a log.

## Option B: watching

Only if the author chooses option B. One more key and two more rows:

| Key | Values | Default | Row |
| --- | --- | --- | --- |
| `clipboard_watch` | `true`, `false` | `false` | *Also record copies from other apps* (disabled with a reason when history is `off`) |
| `clipboard_never_from` | bundle ids | 1Password, Bitwarden, Keychain Access, Passwords | *Never record from these apps* |

Turning the switch on shows a sheet before anything is watched: what is recorded, what never is (the
table above), that macOS may ask each time, and *Turn on* / *Cancel*. While it is on, the Privacy page
adds `CLIPBOARD_WATCH_PRIVACY_LINE`, verbatim from ADR-0066 item 8:

> While Marxy is running it also records what you copy in other apps, except concealed, transient and
> auto-generated items, apps you excluded and text that looks like a secret; it keeps them as above and
> sends nothing anywhere.

If macOS refuses Marxy's read, the switch turns itself off and the row says: "macOS is not letting
Marxy read what other apps copy. History keeps copies made in Marxy." with *Open Privacy & Security…*.
