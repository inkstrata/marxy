## The defect that makes the cycle refuse a planner pull request

`scripts/lib/own-row.mjs` `reviewBoundary` sets `story` to `edits.before` whenever another key
changed. For a row created in the same pull request, `before` is null. `orchestration/cycle.mjs`
`prFacts` then has no row, so `allowed` is empty.

The change that makes #221, #228 and #234 landable by the cycle, without editing their diffs:

In `reviewBoundary`, when `before` is null and `after` exists, govern by `after`. An existing story
that edits someone else's row still governs by its base row, so it still cannot widen itself by
touching the board. A test in `scripts/lib/own-row.test.mjs`: a new key whose Paths list
`docs/plan/jira-issues.csv` and `orchestration/deps.json`, plus an edit to another row, yields
`story.Key` equal to the new key and `story.Paths` equal to the head row. `orchestration/cycle.mjs`
needs no separate change once `boundary.story` is that head row, provided the head Paths cover the
diff. This is not filed as a row in this pull request: adding it here would be the edit this pass
is avoiding. It unblocks Phase 2, so it is not deferred with the other ops work. Hot-patch it, or
land it as its own pull request that touches only its own row.
