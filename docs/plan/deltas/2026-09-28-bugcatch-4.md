## What the pass found

One finding — a wrong score cutoff in the palette's heading search (`headingCouldBeat` used
`10_000` as `fuzzyScore`'s ceiling when the true maximum is `10_500`, so an exact heading match
could be skipped in favour of a worse title match, both mis-ranking the result and losing its
heading-jump target) — was small and well-verified enough to fix directly, and landed as a fourth
commit on the still-open MARXY-290.

Two more findings, both in the orchestrator's own machinery, are filed here rather than fixed
directly, for the same reason the third pass's CI-gate findings were filed: this machinery runs
on every PR in the fleet, and a rushed fix risks a worse regression than the bug it fixes.

| Key | Area | What's wrong |
| --- | --- | --- |
| MARXY-311 | ci/gates | `check-cards.mjs`'s `\Z` (a literal char, not an end-of-string anchor in JS) makes its path-boundary check a silent no-op for any task card whose "Files and signatures" section is last — the common case |
| MARXY-312 | ops | `pnpm done`, re-run after a branch regresses, leaves a stale "done, all gates ok" result on disk that a reviewer or the fleet's own adoption logic can be shown as current |

The pass also re-read `packages/core/src/sanitize/` and `packages/core/src/render/highlight.ts`
in full — the security-critical HTML-sanitization boundary — hand-tracing concrete crafted
payloads (entity-encoded `javascript:`, scheme-case bypasses, SVG/MathML namespace bypasses,
mXSS via highlighter output re-entering unsanitized markup) against the actual code. No bypass
was found; the sanitizer held up.

A lower-confidence candidate (a double space before a typeset-forced line break possibly leaving
a stray leading space, `packages/typeset/src/apply.ts`/`runs.ts`) could not be confirmed without
an empirical browser/DOM check and is not filed — recorded here in case a future pass wants to
verify it with a golden-screenshot fixture.
