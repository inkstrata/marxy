# Plan delta — 2026-09-19: the ops lane

Slim rewrite of the discarded PR #52. Process work only. No 2026-09-18 deltas, task cards,
ADR-0015, or taste-review #0.

## What was wrong

`ready.mjs` holds phase N+1 while phase N has todo or in-progress work. Every open Phase 0
story that was still holding the fleet was process, gate or CI work. The page waited behind
improvements to the loop.

## What changed

- A non-numeric `ops` phase in `orchestration/deps.json`. It never holds a numbered phase and
  is never held by one. When an ops story and a phase story want the same path, the phase
  story is dispatched first.
- Moved into `ops`: leftover process, gate, CI and release stories, including this one.
- MARXY-95 (the browser harness) moves to Phase 1 so MARXY-26 no longer depends on a later
  numbered phase.
- MARXY-20 loses `human-gated` so the theme can start once MARXY-75 is done.
- `docs/scope.md` cuts the light variant first; `docs/plan.md` names dark as primary
  (ADR-0024).
- `orchestration/state.json` is gitignored. Jira is the board of record.

## Sequence this produces

MARXY-75 is ready while ops work is still todo, then MARXY-20. Ops stories keep their own
dependencies; they just stop being a phase gate.

## How we would know I was wrong

1. `selectReady` still hides MARXY-75 while only ops stories are open in Phase 0's old slot.
2. An ops story is offered on `packages/theme` ahead of MARXY-20.
3. The three-dot diff includes a 2026-09-18 delta, ADR-0015, or taste-review #0, or exceeds
   ~600 lines.
