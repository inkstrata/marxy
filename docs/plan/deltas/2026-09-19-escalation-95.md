## The escalation: two checks pinned to a path, and the code moved

The reviewer escalated MARXY-95 rather than returning it, correctly. The split itself is good work —
`main.ts` is nine lines, the memory shell records calls, the WebKit harness boots the real app and the PR
shows it failing with the render write emptied. Both blocking problems are one structural fact:
**`apps/desktop/test/paint-signal.test.mjs` and `scripts/registry.json` both enforce behaviour by
naming the path `apps/desktop/src/main.ts`, and this story moves that behaviour into `app.ts`.** Both
pins sat outside the story's boundary, so attempt 1 kept them green without moving them:

1. A comment block in `main.ts` repeating the four strings `paint-signal.test.mjs` greps for, so deleting
   the `first_text` mark from `app.ts` would leave that test green.
2. `Reflect.set(el, 'innerHTML', html)` in `app.ts`, which `check-registry.mjs`'s `/\.innerHTML\s*=/`
   cannot see — the app's only render site, a sanitiser boundary, left the allow-list silently.

**Decision: widen MARXY-95's `Paths`, do not write a follow-up.** A follow-up leaves the decoy comment
and an unwatched render site on `main` until it lands, and a check passing on text that is no longer the
code is worse than a red gate because it also lies to the next reader. The reviewer will not sign #82 as
it stands, so nothing merges either way; and #82 is CONFLICTING, so the branch is being touched again
regardless. The only extra cost is the landing story, which this delta needs anyway.

Criteria 8 and 9 say it: `paint-signal.test.mjs` reads `app.ts` through `stripComments`, `main.ts` carries
no comment repeating those strings, and the PR shows the test red with the mark deleted; `app.ts` writes
`doc.innerHTML = html` plainly, joins `innerHtmlAllowedIn`, and the PR shows `check-registry.mjs` red
without that entry. Attempts stay at 1, so this is attempt 2 inside the cap, and the split stands.

## The second finding: every taste fix but two is blocked, and the two are blocked by the freeze

Taste review #1's verdict on the first styled page is **"not a book yet"** — six named faults — and review
#0 adds two more on pair A. Three Jira issues were filed for them (MARXY-128, 129, 130) and none has a CSV
row, so `ready.mjs` cannot offer them: the invisibility the after-65 pass found for MARXY-93…98. Rows and
cards are written here.

Six of the eight faults are rules in `packages/theme/src/base.css` — heading margins, code-block padding,
italic and strike, the quote rule, checkbox alignment, table padding — which is system-owned and was
never frozen. Those are MARXY-128 and need no decision. The other two are *values*: the mono is slightly
small, the headings shout. They live in `packages/theme/src/tokens.css`, which `pnpm test:contracts-frozen`
pins **byte for byte**, so under `AGENTS.md` as written each costs its own ADR — while the light variant's
values sit unfrozen in `packages/theme/default/theme.css` and dark is primary (ADR-0024). The rule
inverted its purpose: the freeze exists so a theme *author* can rely on the tokens, and an author relies
on names, units and meanings, not on marxy's 28px.

**ADR-0031 (proposed):** the contract is the token names, their unit kinds and their documented meanings;
values are taste and move through a story with a queue row. `check-tokens.mjs` replaces the byte pin on
that one file; every `packages/*/src/contracts/` pin stays. MARXY-133 accepts it and moves no value.
Moving dark's values beside light's is the cleaner end state and ADR-0008 wants it; the ADR says why it
is not this story.
