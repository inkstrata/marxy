## What's actually in PR #142

Read in full (`gh pr diff 142`, 858 lines) before deciding anything, because the shape of the fix
depends on what the branch already is, not just on the error message.

It is a complete, self-contained module. `apps/desktop/src/source/` never imports from `main.ts`
or `app.ts` — `startup-deferral.test.mjs`, already in the PR, asserts exactly that by reading both
files' text for `@codemirror` and `src/source`. Every acceptance criterion the CSV row names is
proved by the module's own standalone Playwright harness (`harness-entry.ts` +
`harness-shell.html`, built with `vite build` and served from a throwaway `http.createServer`, not
the desktop app): per-file-type default (`default-mode.test.mjs`), byte-identical round-trip
(`buffer-commit.test.mjs`, `mode-switch.test.mjs`), the 9 MB / 100 ms scroll budget and multi-cursor
undo (`source-browser.test.mjs`). The PR body says so plainly: *"App shell wiring (Mod+E) is a
follow-on"* and *"Expect a return for the path boundary."* This is the same honest shape MARXY-36's
PR #30 had — good, checked work, wrong Paths cell — not a defect in the code.

This is the mechanism-proving half of the story, structurally identical to MARXY-86 (palette
model). The part MARXY-86/87 split off — mounting into the real DOM with a real assertion — was
simply never attempted here, because the story's own acceptance criteria never asked for it. That
is the gap this delta closes, not a defect to fix in the existing branch.

## The split

**MARXY-37 keeps its key and its branch.** Its Paths widen by exactly one file:
`apps/desktop/package.json`, so the new `@codemirror/{state,view,commands,search,lang-*}`
dependencies can enter the lockfile inside the story's own boundary — the same fix MARXY-86 used
for the same reason, and `pnpm-lock.yaml` itself needs no Paths entry at all
(`docs/hygiene.md`: lockfiles are already allowed outside a story's paths). Nothing else about the
row changes in kind: the Acceptance criteria are restated to name which check proves each one
(the module's own harness, not `main.ts`), so the next reader does not have to re-derive that from
the PR body. **Do not add DOM wiring, a keybinding dispatcher, or an `index.html` mount point to
this story** — that is out of scope by the row's own new Description.

**A new story, `MARXY-169`, takes the view half** — the analogous slice to
MARXY-87. `apps/desktop/index.html` is today `<article id="doc">` and nothing else: no
`#marxy-source` node, no keybinding dispatcher anywhere in `app.ts` or `main.ts`. Phase 2 is
supposed to end with "switches instantly, and has Source mode" (`docs/plan.md`); a module that
proves its own logic in a harness nobody ships is not that. The new story adds the mount point,
wires `Mod+E`, and asserts against the real document the app boots — reusing MARXY-37's exported
functions (`defaultModeForPath`, `createSourceEditor`, `leaveSourceMode`,
`modeRoundTripWithoutEdits`) rather than re-deriving any of them. First time a reader sees
CodeMirror in the shipped app, so it carries a `docs/taste-review/queue.md` row. Depends on
MARXY-37 and MARXY-95 (`startApp` split, so the toggle has a clean seam without touching startup
timing).

One risk named rather than fixed: **MARXY-87 (palette view) is also unwired**, and will also want
to add the first keydown dispatcher to `app.ts` for `Mod+P`. Both new/updated rows list
`apps/desktop/src/app.ts`, so `ready.mjs`'s path-overlap check will not dispatch them concurrently
— but whichever lands first should leave a small, extensible dispatcher rather than a competing
`addEventListener('keydown', …)`, and the new story's card says so. This is the same shape of risk
`docs/plan/deltas/2026-09-19-marxy-26-split.md` named for `fixtures/baselines` having four owners;
here it is one file with two owners, sequenced only by `deps.json` and path overlap.

## Why not just widen Paths and stop there

Widening MARXY-37's Paths alone would unblock CI and let PR #142 merge as-is — and that is exactly
what this delta does for MARXY-37. But it would leave the story's own row implicitly claiming
"Source mode" is done for v0.2 purposes when nothing reaches a reader. The trigger's own framing
("use analogous vertical slices for Source mode") and `docs/plan.md`'s phase-2 exit criterion both
say the view half needs its own tracked story now, not a silent assumption that some later story
(MARXY-47, MARXY-49) will wire it in as a side effect. Checked: MARXY-47 ("opening `theme.css`
lands in Source mode") and MARXY-49 ("save … from either mode") both drive the module directly
through their own app-test harnesses and do not need `main.ts`/`Mod+E` wiring to exist first — their
`depends:` stay unchanged at MARXY-37. MARXY-39 (taste review #2) also stays unchanged: its own
card already says its Source-mode screenshot is "via the headless entry," i.e. MARXY-37's own
harness, not the mounted app.

## Escalation risk

**Low for MARXY-37 itself** — the fix is mechanical (one Paths cell) and the branch already
passes every other gate (`changes`, `conventions`, `browser`, `gates-record`, `gates
(macos-latest)`, `gates (ubuntu-latest)` all green on PR #142; only `fast`/`ci` are red, and both
for the same resolvable reason). **Watch MARXY-169**: it is the first story to
add a keydown dispatcher to `app.ts`, a mechanism no prior story has touched, and it depends on
reusing MARXY-37's exports correctly rather than re-deriving byte/UTF-16 mapping — if an
implementor re-implements `scrollSourceToByte` instead of importing it, that is exactly the
"mechanism no prior story has touched" flag this section exists for.

## How we would know I was wrong

1. **PR #142 still fails `fast`/`ci` after the Paths widening and a rebase.** Then the CodeMirror
   dependency resolution failure has a second cause this pass did not find, and the next pass
   should read the exact TypeScript error text, not just its shape.
2. **MARXY-169 returns for touching `apps/desktop/src/source`.** Then "reuse, do
   not re-implement" was not specific enough about the module's export surface, and the fix is a
   named import list in the card, not a bigger Paths grant.
3. **MARXY-87 lands first and adds a dispatcher the mount story cannot cleanly extend.** Then the
   "whichever lands first leaves a seam" note was optimistic, and a future pass should give one of
   the two stories the dispatcher itself as an explicit, separate, small story both depend on.
