## What the pass found

Two small, low-risk findings landed directly as a third commit on the still-open MARXY-290: a
palette heading-jump losing its byte offset for a Source-default file (always landing on byte 0
instead), and a stale comment in `tokens.css` claiming the loader clamps two tokens it doesn't
(base.css does, at runtime).

The eight filed here needed more design work, more test surface, or — for the four CI-gate
findings — the kind of careful testing a shared safety net deserves rather than a same-day patch:

| Key | Area | What's wrong |
| --- | --- | --- |
| MARXY-302 | desktop | Source-mode reading position is frozen at entry time; scrolling inside CodeMirror never updates it |
| MARXY-303 | desktop | Rapid edits can start two overlapping deferred-startup runs; an older one can overwrite the palette index with stale entries |
| MARXY-304 | desktop | A failed `shell.quit()` after a successful render overwrites the page with an error |
| MARXY-305 | desktop (Rust) | The main window's Tauri capability grants full menu-manipulation rights beyond what's used, undermining the Rust-side native-menu allowlist's guarantee |
| MARXY-306 | ci/gates | `check-registry.mjs`'s innerHTML/outerHTML route regex misses `+=` |
| MARXY-307 | ci/gates | `check-boundaries.mjs`'s dynamic-import spec extraction misses a template-literal import |
| MARXY-308 | ci/gates | `check-deps.mjs` misses Cargo's `[dependencies.crate-name]` table syntax |
| MARXY-309 | ci/gates | `gate-bundle.mjs` misses a dynamic import, and can be invoked pre-build with both its checks effectively skipped |

The four `ci/gates` findings share a theme: each is a real false-negative in a script whose whole
job is catching a violation (a network/telemetry leak, a forbidden dependency, an unsanitised
HTML write, a bundled dev-only shell). None is exploited today as far as this pass found, but
each is a gap in the project's own safety net, worth fixing carefully rather than in the same
pass as a dozen other patches.

## What this pass does

All eight rows sit in the **ops lane** (no phase). **Phases 0–4 in `orchestration/deps.json` are
unchanged.** None of the eight depend on each other or on in-flight work, including the still-open
MARXY-290.

## Findings re-checked and confirmed as already handled, not new

As in the second pass, some third-pass reports re-flagged the already-fixed `ch`/`px` clamp
bypass in `loader.ts` — correct for `main`, which doesn't yet include MARXY-290's unmerged
commits, but not a new finding.

## Not filed, and why

- **`apps/desktop/src/shell/memory.ts`'s `assetUrl` leaking object URLs** (no `URL.revokeObjectURL`
  ever called): a genuine resource leak, but test-only harness surface (the memory shell backs
  Playwright tests, not the production Tauri shell) — low real-world impact, not worth a story.
- **`packages/core/src/index.ts`'s public entry point omitting most of the package's own module
  map** (operations/, render/, sanitize/, index-model/): every consumer in the tree already reaches
  through deep import paths instead of the bare `@marxy/core` specifier, consistently, so nothing
  is actually broken — an API-surface inconsistency worth a note, not a story.
- **`apps/desktop/src-tauri/src/index/mod.rs`**: not wired into any Tauri command yet (dead code,
  presumably staged for a future indexing story) — no reachable surface to review.
