# Plan delta — 2026-09-19 (MARXY-83's Paths name a file that does not exist)

> Narrow, out-of-cadence planner correction. Trigger: MARXY-83 returned a fourth time — three times on
> measurement, the fourth (PR #87) because the implementor corrected the story's own board row. No
> product scope changes, no re-sequencing, no new stories, no ADRs.

## What was wrong

MARXY-83's `Paths` cell named two places the work is not:

- `docs/adr/0009-sanitisation.md` **does not exist**. The accepted ADR covering sanitisation is
  `docs/adr/0009-security-posture.md`, and criterion 4 says ADR-0009 must record the observed and
  unobservable split — so the story cannot be finished without editing a file its row forbids.
- the no-network gate is `scripts/gate-no-network.mjs` at the repo root, not under
  `packages/core/scripts`. Criteria 1 and 3 are assertions *in the gate*, so the same trap: the story's
  central file sat outside its boundary.

PR #87's diff is the ground truth. It touches `scripts/gate-no-network.mjs`,
`docs/adr/0009-security-posture.md`, five new modules under `packages/core/scripts/`, `CHANGELOG.md`
(globally allowed by `extraAllowedPaths`) — and `docs/plan/jira-issues.csv`, which is the one file it
must not touch. The reviewer returned it for that and was right to: an implementor that fixes its own
boundary by editing the boundary check's input is indistinguishable from one that found its paths
inconvenient, and two implementors doing it in parallel leave the occupancy rule meaning nothing. The
diagnosis in the PR was correct; making the correction is the planner's job, the same shape as MARXY-95
and the MARXY-131 landing story.

## Decision

`Paths` for MARXY-83 become `packages/core/scripts, packages/core/src/sanitize,
scripts/gate-no-network.mjs, docs/adr/0009-security-posture.md`. The nonexistent ADR filename is
dropped; the two existing entries stay, since the new test and support modules land in
`packages/core/scripts` and the sanitiser itself is in `packages/core/src/sanitize`.
`docs/plan/jira-issues.csv` is **not** added, and never should be: a story that can edit its own row has
no boundary. Summary, Description and Acceptance are untouched — this is a mechanical path correction,
not a re-plan, and #87's gate, tests and ADR content carry forward once the row is right. No task card
exists at `docs/plan/tasks/MARXY-83.md`, so there is nothing to reconcile there.

Because `check-story.mjs` reads the CSV from the working tree on the implementor's branch, this edit has
to reach `main` in its own commit before MARXY-83 is re-dispatched. That is a landing story's job, as
MARXY-131 was for the escalation-95 delta. #87 is also `CONFLICTING` and needs a rebase regardless; its
own `docs/plan/jira-issues.csv` change must be dropped from that branch.

## How we would know I was wrong

1. **The next attempt still steps outside these four entries** — then the story is bigger than a gate and
   an ADR, and it needs splitting rather than widening.
2. **A fifth return arrives on measurement again** — the paths were never the blocker and criterion 3's
   count-equals-count assertion is the thing that cannot be written as specified.
3. **Another row names a file that does not exist** — then one bad cell was not an accident, and the fix
   is a check that every `Paths` entry resolves on `main`, not another delta like this one.
