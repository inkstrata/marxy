## The finding: `earlierPhaseOpen` doesn't distinguish "blocked" from "gone"

`ready.mjs` correctly refuses to *offer* a `human-gated` story for dispatch. It does not remove that
story from `earlierPhaseOpen()`'s count of what is still `todo`/`in_progress` in an earlier numbered
phase — so a human-gated story sitting in phase 1 holds phase 2 (and everything phase 2 gates in
phase 3) open exactly as hard as a story that is genuinely in progress. Two stories were doing this,
both stalled on a human answer this repo has been waiting on since before the last plan:

- **MARXY-22** (Linux weight harness) — `human-gated` since 2026-09-19, waiting on `needs-human.md`'s
  2026-09-18 question ("Say whether a Linux desktop exists for MARXY-22") that the author has not answered.
- **MARXY-94** (ADR-0026 shell-api amendment) — `human-gated`, `contracts`, waiting on the author's ruling on
  a proposed ADR since 2026-09-19.

Checked directly, with `state.json` copied read-only into this worktree and every story marked `done`
except these two, MARXY-33 (2, 118) and everything phase-2/3:


Every one of those `blockedByDeps` entries has its own real dependencies already satisfied
(MARXY-33's are MARXY-21/27/28/35, all `done`) — the block is `earlierPhaseOpen`, not a dependency
edge. Neither MARXY-22 nor MARXY-94 is a reader-facing phase-1-end promise
(`docs/plan.md`'s Phase 1 "ends with" list names neither), and `orchestration/deps.json`'s own `deps`
map lists **no dependent at all** for MARXY-22 and only phase-3 dependents (MARXY-49, MARXY-97) for
MARXY-94 — both of which stay correctly gated by the dependency edge itself once the phase gate stops
also holding them. This is exactly the precedent `docs/plan.md`'s ops lane already exists for
(MARXY-15/59/65/70/77/78: "process, gate, CI and release work... beside the phases, never in front of
them") — MARXY-22 and MARXY-94 are governance/hardware-measurement concerns, not page features, and

## Escalation risk

- **MARXY-164 and MARXY-33 both need `apps/desktop/src/app.ts`.** If `state.json` is not reconciled
  for MARXY-33's open PR #137 first, dispatching both in the same round produces a guaranteed path
  collision — not a hard story, a scheduling hazard. Low risk once sequenced correctly; flagging so
  it is sequenced correctly.
- **MARXY-164 is new territory**: it is the first story to build the `IntersectionObserver`
  lazy-highlight pattern `apps/desktop/src/render/images.ts` already established, applied to a
  different element shape (`pre > code` runs of trusted-DOM spans rather than a single attribute
  swap). Watch for the token-to-span replacement running before the element is actually visible
  (defeating the point of lazy highlighting) or after `first_text` in a way that causes layout shift
  the CLS gate would catch — if it returns twice, that is a sign the lazy-visibility contract needs
  its own design-doc paragraph before a third attempt, not a third narrow fix.
- **MARXY-163 is low risk** — it cherry-picks a commit that already exists, was already reviewed once
  (informally, as part of PR #135's now-abandoned diff), and touches four files with no new
  mechanism.
- **The `earlierPhaseOpen`/human-gated interaction itself** is a real mechanism gap this pass routed
  around by re-lanning two stories rather than fixing in code (the planner does not implement
  `orchestration/*.mjs` logic). If a third human-gated story appears in a numbered phase with no real
  dependents, re-laning it the same way is the right move again; if a *fourth* one appears with real
  in-phase dependents that legitimately should hold the phase, that is the signal to write an ops
  story that changes `earlierPhaseOpen` itself to skip `human-gated` stories, rather than keep
  re-laning case by case.
