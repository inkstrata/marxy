## What the pass found

Three of the highest-confidence findings were small enough to fix directly in the same-day
out-of-plan PR MARXY-290 is carrying (a second commit on that branch, since the PR was still
open): a `config.toml` data-loss bug where `setTopLevelKey` only rewrote a key's *opening* line,
corrupting the file when the old value was a multi-line array; a palette pin-toggle
(Cmd/Ctrl+.) that pinned an empty-string path when no hit was selected; and a `read_dir`
directory-iterator error (distinct from the per-entry `metadata()` race already fixed) that
still aborted the whole listing.

The five filed here needed more design or test surface than fits alongside a same-day patch:

| Key | Area | What's wrong |
| --- | --- | --- |
| MARXY-295 | core | `sectionRange` only walks top-level blocks, so a heading nested in a blockquote/list gets the wrong section boundary |
| MARXY-296 | core | Widow prevention's `lastTextNode` doesn't see a paragraph ending in code/image/math, though the word-count gate counts them |
| MARXY-297 | core | The index's fence-tracking heuristic toggles on either fence character, not just the one that opened the fence |
| MARXY-298 | typeset | The `--marxy-typeset: none` kill switch is checked only at attach/relayout time, not during background/scroll-triggered typesetting |
| MARXY-299 | desktop (Rust) | An unrelated broken/vanishing symlink in the watched root fails the whole `watch_root` call |

## What this pass does

All five rows sit in the **ops lane** (no phase), for the same reason as the first pass's filed
stories: this is correctness work in already-shipped machinery, not new phase build-out.
**Phases 0–4 in `orchestration/deps.json` are unchanged.** None of the five depend on each other
or on in-flight work, including the still-open MARXY-290.

## Findings re-checked and confirmed as already handled, not new

Reviewers working from a static instruction set naturally re-read the *main* branch, which does
not yet include MARXY-290's unmerged fixes. Several second-pass reports flagged the
already-fixed `data:` URL bypass, `ch`/`px` clamp bypass, stale dirty-flag baseline, `read_dir`
per-entry `metadata()` abort, and `unwatch_root` canonicalize-mismatch leak as still present —
correctly, for `main`, but these are not new findings; they land with MARXY-290. Two watcher
mutex-blocking points reported again duplicate the already-filed MARXY-286.

## Not filed, and why

- **`apps/desktop/src/notices/blocked.ts`'s `blockedContentNotice` unconditionally calling
  `clearNotices()` on every render:** a real design wart (it can dismiss an unrelated visible
  notice sooner than expected) but the reviewer could not construct a concrete corrupting
  scenario beyond "a notice disappears sooner than expected" — worth a look during unrelated
  notices work, not its own story.
- **A dash-break token possibly dropped in `runs.ts`'s `collectTokens` when a dash is immediately
  followed by whitespace, an IntersectionObserver/queue race, and a hyphen-probe DOM mutation
  mid-measurement in `measure.ts`:** all traced by hand and found correct or functionally
  harmless once a concrete example was worked through.
- **The remaining watcher mutex-blocking points** (`watch_root` holding the table lock across a
  slow `spawn_poll_thread` call; `unwatch_root` holding it across the thread join): already
  covered by MARXY-286's acceptance criteria 2 and 3.
