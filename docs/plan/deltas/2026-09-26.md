## The finding: MARXY-48's Paths could not hold the feature

The implementor wrote outline, find, the Rust editor command and a keyboard test (24 files,
1,324 lines, uncommitted). It stopped because the harness would not pass, and it named three
follow-ups. Each one is a file its row did not list:

1. **`apps/desktop/src/selection/bind.ts`.** `installCommandKeys` already binds every registry
   command, but `keyMatches` compares `event.key === key`. With Shift held, `event.key` is `"O"`, so
   `Mod+Shift+O` can never fire. Unable to edit it, the implementor wrote a second matcher in
   `palette/keys.ts`.
2. **`apps/desktop/src/app.ts` and `main.ts`.** Nothing tells an overlay that a document is on the
   page, or that background typesetting has finished. Without them, the implementor mounted outline
   and find with a `MutationObserver`, a `requestAnimationFrame` loop and a 100 ms `setInterval`.
3. **The harness.** `app.html` has no `#marxy-outline` or `#marxy-find`, and `app-harness.ts` calls
   `startApp`, not `bootApplication`. So no test could exercise the production mount. The ±2 px
   landing was flaky because find scrolled before typesetting finished. `app.ts` already solves
   that for opens with its anchor (`landOn`/`holdAnchor`), and find could not reach it.

The card said to split only if a reviewer returned the story. This is a different failure. The
row asked for work its Paths forbade, and a second attempt on the same row would fail the same
way. So this pass splits it along the seam the card already named.
