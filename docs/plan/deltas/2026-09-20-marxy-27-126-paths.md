## Trigger A — PR #124 (MARXY-27) returned for self-widening `Paths`

`docs/plan/jira-issues.csv`'s MARXY-27 row listed `Paths` as `packages/core/src/highlight,
scripts/allowlists`. The implementor needed `packages/core/package.json` too — Shiki is a new
`packages/core` dependency, and ADR-0006's allow-list already names the package, so this is a
legitimate need, not scope creep. Finding the row too narrow, the implementor edited
`docs/plan/jira-issues.csv` itself in the same PR to widen it — exactly the boundary only a
planner or a landing story may cross (`AGENTS.md` "one issue, one branch... do not edit files
outside your issue's listed paths"; the CSV is the spec the hook enforces, not a file any story's
own `Paths` ever names) — and the review correctly returned it for that, not for the dependency
itself.

**Fix:** widened MARXY-27's row to `packages/core/src/highlight, scripts/allowlists,
packages/core/package.json`. This legitimizes the dependency file only. It does **not** retroactively
bless the `docs/plan/jira-issues.csv` hunk #124 itself carries — that edit is still out of bounds
regardless of what the row now says, because it happened on the story's branch rather than a
planner's. The implementor's next push should drop that hunk from the diff; everything else in
#124 (the highlighter, the allow-list loader, the gates, `pnpm-lock.yaml`, `CHANGELOG.md`) already
sits inside `Paths` or the always-allowed set once `package.json` is added. **#124 stays open** —
this is a fix-forward on the existing PR, not a new attempt, and nobody should start a second
MARXY-27 implementor while it is outstanding.

**MIT check (explicit, since it gates the widening):** `@shikijs/core` and the allow-listed
`@shikijs/langs` grammars are MIT/BSD-family per ADR-0006's allow-list, and #124's own verification
already ran `gate:licences` green before it was returned — the widening changes nothing there, it
only lets the dependency file itself land inside the story's boundary. No new licence-gate work
follows from this delta.
