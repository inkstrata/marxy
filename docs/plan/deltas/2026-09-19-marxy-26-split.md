# Plan delta — 2026-09-19 (MARXY-26: a story whose acceptance lived outside its paths)

> Out-of-cadence planner pass. Trigger: MARXY-26 escalated on attempt 1 (PR #95, reviewer verdict
> `escalate`); MARXY-128 escalated in the same wave (PR #94) on a conflict with an accepted ADR; plus the
> two leftovers this wave's needs-human items named. No phase moves and no scope cut. One ADR amendment,
> for MARXY-128: everything the MARXY-26 split decides is already written in `docs/design/02-render.md`,
> `docs/design/06-shell.md` and ADR-0026/0027, and the story rows simply did not match them.

## What happened

MARXY-26 carried three acceptance criteria and `Paths` of `packages/core/src/render,
apps/desktop/src/shell`. None of the three can be satisfied from inside those two directories:

1. *"CLS = 0 across image decode on `02-readme-real-world.md`"* — all four images in that fixture are
   remote (`example.invalid`, three `img.shields.io` badges) and `main` already strips a remote `src`.
   Nothing decodes, so CLS is 0 with the diff reverted. The criterion was true before the story existed.
   **No corpus document has a local image whose file is present**: `09-gfm-everything.md` references
   `image.png` and `05-pathological-table-and-nesting.md` references `nope.png`, and neither file is in
   the tree.
2. *"every remote image in `10-hostile.md` is replaced by an inline notice naming its host"* — the notice
   is app chrome. It lives in `apps/desktop/src/notices/` (design §09) and cannot be in the article,
   because the goldens and `hostile-fixture.test.ts` correctly forbid a hostile host string in rendered
   HTML. PR #95 built the data a notice needs (`RenderResult.blockedImages`, `blockedImageNoticeText`)
   and has no caller anywhere in the tree.
3. *"local images resolve through `shell.assetUrl` scoped to the document directory"* — dead in three
   independent ways: `tauri.ts` invokes `allow_asset_scope`, which is not in `main.rs`'s
   `generate_handler!`; `tauri.conf.json` still has `assetProtocol.enable: false`; and nothing calls
   `assetUrl`. What the PR checks instead is a `readFileSync` of `tauri.ts` asserting the strings
   `imageSize`, `allowAssetScope`, `assetUrl` and `convertFileSrc` appear in it — a grep for member
   names that a stub throwing on every call would pass.

The code in PR #95 is good: `resolveImageSrc` implements ADR-0027 §5 exactly, `collapsePath` returns
`null` rather than a string when `..` escapes, hosts are derived through the sanitiser's own
`sanitizeUrl` so the notice and the removal report cannot drift, and the core suite is 448/448. This is
the third story in this class (MARXY-36, MARXY-66, now MARXY-26): **the `Paths` cell was narrower than
the acceptance the row carried.** A second attempt could not have changed the verdict, which is why the
reviewer escalated instead of returning.

## The split

**MARXY-26 keeps its key and becomes the core half, and loses `apps/desktop/src/shell` from its paths.**
That is a deliberate narrowing rather than the obvious `26a`/`26b` lettering: PR #95's core module is
mergeable as it stands, and its acceptance is rewritten to the five things a unit test can actually
prove — hosts reported in document order with each named once, `/x.png` against the image root and a
`../` that leaves it refused, a box reserved and scaled from the aspect ratio, `assetUrl` never reached
for a refused or remote src, and the notice *text* built as data that no core code inserts into HTML.
Criterion 6 forbids the failure mode directly: no test in that PR may assert a member name's presence in
another package's source text, and none may read a file under `apps/`.

The shell members (`imageSize`, `allowAssetScope`, `assetUrl`) go out of MARXY-26 entirely and into the
new story with the Rust that makes them work. The implementor reverts the `tauri.ts` and `memory.ts`
hunks on the branch; the new story's card says that the shape at `89709c8` is the intended shape and to
re-land it wired to real commands. The point is that **nothing about asset scoping reaches `main` until
the Rust side does, in one commit** — the ordering hazard the reviewer named goes away instead of being
documented.

**MARXY-138** takes the rest: the two Rust commands, `assetProtocol.enable = true`
with an empty scope, post-pass 3 in `apps/desktop/src/render/images.ts`, the notices region and the
blocked-content notice, and the call site in `app.ts`. Three things I put in it that were not in the
old row:

- **`fixtures/corpus/image.png`, 1200×400.** The CLS criterion is unsatisfiable without a local image
  that decodes, and `09-gfm-everything.md` already references `image.png` relatively, so adding the file
  changes **no existing document byte** and no golden — the goldens are parse-level. Wider than the
  measure on purpose, so the same fixture exercises the scale-down and the recomputed reserved height.
  The reviewer suggested a separate corpus story; I folded it in because a fixture whose only purpose is
  to make this story's own criterion non-vacuous is part of this story, and splitting it would leave the
  criterion vacuous for as long as the two rows sat apart.
- **A standing check that every `invoke(name)` in `tauri.ts` is registered in `generate_handler!`.**
  This is the mechanism the escalation is really about. A TypeScript shell method calling a command that
  does not exist is invisible to typecheck, lint, the unit suite and the review — it only fails at
  runtime in a packaged app, which no gate launches with a document open. The check goes in the existing
  `apps/desktop/test/shell-boundary.test.mjs` and has to be shown failing when a name is removed from
  the handler list. Every future shell story inherits it.
- **Zero CLS measured rather than asserted.** A `PerformanceObserver` on `layout-shift` from before the
  post-pass until the image's `decode()` resolves, summed value 0, plus `naturalWidth > 0` so the test
  proves something decoded. Shown failing once with the `width`/`height` assignment removed.

`img-src` in the CSP is **not touched**: it already carries `asset: http://asset.localhost`, so step 5
of the old task card is already done, and MARXY-45 owns the final CSP. A criterion asserts the CSP
string is byte-identical to `main`'s, so the story cannot pre-empt MARXY-45 by accident.

## `imageSize` stays in Rust; core keeps the pure reader as a fallback

Reviewer note 4 asked which survives, the TypeScript header reader in PR #95 or the `imagesize` crate
`docs/design/06-shell.md` names. **The crate.** Two reasons, neither of them "the design document says
so": reading a header in TypeScript means the shell reads the *whole file* through `readFile` to learn
two integers, once per image; and it puts a parser for attacker-controlled bytes in the renderer process
rather than the privileged one that already has the file open. `imagesize` is MIT and reads the header
only.

`imageSizeFromBytes` stays in `packages/core` as the pure function the memory shell and the unit tests
use, so a test never needs Rust. The new story adds one sentence to §06 saying exactly that, so the
repository does not end up with two readers and no statement of which is shipping.

## The two needs-human leftovers, now stories

- **`scripts/registry.json` still lists `packages/theme/src/tokens.css` as frozen.** MARXY-133 landed
  ADR-0031 and removed the byte pin from `test:contracts-frozen`, but `check-story.mjs` reads
  `registry.json`'s `frozen` array and refuses any change to a listed file unless a `docs/adr/*.md` is
  in the same commit. MARXY-129 is a *tune* — values only, no ADR by ADR-0031's own decision — so it
  would be refused at commit time by a rule ADR-0031 retired. `MARXY-139`
  removes the entry, points the boundary at `scripts/check-tokens.mjs` instead, and MARXY-129 gains it
  as a dependency. Small, but it is the difference between MARXY-129 being ready and being blocked.
- **`apps/desktop/src/app.ts` still passes `hyphenate: false, hanging: 'none'`.** MARXY-24 landed
  hyphenation and left-edge hanging with defaults of `true` and `'left'`, and correctly did not touch
  `app.ts`, which is outside its paths. So the two features exist and the reader does not see them.
  `MARXY-137` is the one-line change **plus the baseline recapture**, which is
  where it stops being a one-liner and becomes the right owner: turning both on moves every line of
  every screenshot, so it has to regenerate `fixtures/baselines` and carry the taste-review row. That
  makes its own diff the before/after artifact the queue wants.

This also answers the sequencing question in the needs-human item. MARXY-25 is in review now and
commits the first baselines; by construction they describe the un-hyphenated, un-hanging page. **Let it
merge anyway** — the gate is the value, and a baseline that is wrong for a day is cheaper than holding
the only mechanical aesthetics gate. Dispatch the typeset-defaults story immediately after it lands, and
the whole-corpus movement in its diff is the artifact. The images story then recaptures the two
documents that gain an image. That ordering is why `app.ts` overlap makes the typeset story a dependency
of the images story rather than a parallel one.

## The second escalation in the same wave: MARXY-128 and ADR-0030

PR #94 escalated for a different reason that is also the planner's: its table rule contradicts an
**accepted** decision record. ADR-0030 decision 3 says tables sit on the grid by construction, one line
box per row with rules as inset shadows that take no height, and decision 4 lists what `snapToGrid` pads
with tables deliberately absent. #94 gives a table the code line box and half-unit cell padding, so a row
is 50 px and a table is no longer a whole number of grid units. The PR says so honestly and updates
`docs/design/05-theme.md`, but `docs/adr/` is outside its paths, and reverting the rule is not available
either because its own criterion 7 requires it.

The reviewer measured the departure rather than asserting it: re-adding `01-long-technical.md` to
`grid.test.mjs`'s `TEXT_ONLY` set — the set the stylesheet alone must hold *without* the grid pass — fails
at #94's head, with ten blocks 8 px off the 14 px unit starting at the first block after a table. Every
corpus file still passes after the grid pass, so the page is correct in the app. **What moved is the "CSS
alone" guarantee**, and `TEXT_ONLY` narrows to one fixture.

**MARXY-141** is the amendment, in its own PR as AGENTS.md requires: tables move into the `snapToGrid`
set, decision 3's heading construction is restated, decision 2's numbers are stated as unchanged, and the
narrowing of `TEXT_ONLY` is recorded with the ten offsets as evidence rather than being allowed to happen
quietly. MARXY-128 now depends on it, which is the honest expression of "then this head merges as-is".
I am not amending ADR-0030 myself: the planner writes the story and the ADR proposal, and an accepted ADR
changes in a PR that touches only that.

Two of the four rejected shapes, for the record. A *superseding* ADR is wrong because only two of four
decisions move. Widening MARXY-128's paths to include `docs/adr/` is wrong for the reason MARXY-83's PR
#87 was returned: a story that can edit the record it is judged against has no boundary.

## Risks that moved

- **Down:** the class of defect where a shell method invokes a command nobody registered stops being
  discoverable only by reading `main.rs`. One check, every future shell story.
- **Down:** "CLS = 0" stops being a criterion that passes because nothing loads.
- **Up, mildly:** `fixtures/baselines` is now named by MARXY-25, the typeset story, the images story and
  MARXY-30. Four owners of one directory, sequenced only by `deps.json`. If two of them are ever
  dispatched together the overlap check should catch it; if it does not, that is the tripwire below.
- **Unchanged:** no network, no telemetry, no document byte touched. The notice builds host text with
  `textContent`, never `innerHTML`, which matters because host names come from a hostile document —
  `registry.json` permits `innerHTML` under `apps/desktop/src/notices.ts`, and this story declines the
  permission.

## How we would know I was wrong

1. **The images story returns twice.** Then it is still too big — the honest next split is the Rust and
   the asset scope in one story, the notices region in another, and the post-pass last.
2. **The `invoke` ↔ `generate_handler!` check finds nothing on `main` after it lands.** Then the defect
   was a one-off in `tauri.ts` and the check is ceremony; it should still stay, because it costs one
   test, but I claimed a class and would have found one member of it.
3. **CLS turns out not to be 0** with `width`/`height` set from a 1200×400 image scaled to the measure.
   Then the reserved height is being computed after insertion rather than before, and §02 post-pass 3's
   "recomputed from the aspect ratio *before* insertion" needs to become a stated invariant in the grid
   pass rather than a sentence in a design document.
4. **A fourth story wants `fixtures/baselines`.** Then that directory needs an owner and a regeneration
   command rather than four stories each regenerating it by hand.
5. **`TEXT_ONLY` still holds one fixture at the end of Phase 1.** Then the ADR-0030 amendment recorded a
   cost and nobody paid it: "the stylesheet alone puts text on the grid" would be a claim checked on a
   single document, which is a gate in name only, and it needs a story that either restores the guarantee
   for documents with tables or drops the claim.
