## The finding: MARXY-195's pin test never quits

PR #227 was returned three times. The first two were a stale base and red `conventions`/`ci`.
The third is a review, and it is blocking:

Acceptance criterion 2 requires launch 1 to open A, then B, pin A, **quit**, and launch 2's
empty palette to list A then B. The test `palette empty query lists pinned document before MRU
after relaunch` in `persist-reading.test.mjs` does not quit. It builds a session with a freshly
imported `emptySession`, writes `history.json` through `serializeHistoryFile` and
`writeFileAtomic`, and would pass if `flushPaletteHistoryFromApp` and the wrapped `quit` were
broken.

The story also does two reader-visible things that do not have to land together: where the
document opens, and which documents the palette lists. The returned branch
(`origin/feat/MARXY-195-remember-reading-across-launches` at `b82dc8e`) already has both. A
second attempt on the same row would be asked to satisfy a criterion its test can fake. So this
pass splits on that seam.
