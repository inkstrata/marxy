## The mechanical fact the trigger's framing got half right

The trigger brief offered two options and asked which was cheaper: "(a) capture real before/after
PNGs under `docs/taste-review/2026-09-marxy-138/`... (b) seed first-ever webkit-macos baselines,"
adding "if AC11 can be met on #115 by adding the PNG directory only ... say that: no landing,
same PR." That premise does not hold, checked directly:

```
$ node -e "import('./scripts/lib/repo.mjs').then(r => {
  const p = r.pathsOf(r.story('MARXY-138'));
  console.log('taste png =>', r.allowedByPaths('docs/taste-review/2026-09-marxy-138/x.png', p));
  console.log('fixtures/baselines png =>', r.allowedByPaths('fixtures/baselines/webkit-macos/x.png', p));
});"
taste png => false
fixtures/baselines png => true   # (before this pass's Paths edit)
```

`scripts/registry.json`'s `extraAllowedPaths` names exactly `docs/taste-review/queue.md` — one
file, not the directory tree beneath it — so a same-named `docs/taste-review/2026-09-marxy-138/`
subdirectory needed its own entry in MARXY-138's `Paths`, the same way `MARXY-128` and `MARXY-129`
each carry their own `docs/taste-review/<slug>` directory in their row. MARXY-138 never had one.
`fixtures/baselines` (option b) *was* already in `Paths` — seeding the first-ever `webkit-macos`
baselines there would have needed no landing. But the standing instruction is right to prefer (a):
seeding pixel baselines with no upstream pixelmatch consumer (`MARXY-30`'s job, not this row's)
would be dead weight nobody diffs against, while (a) is the established, working taste-review
mechanism this story is supposed to use anyway (it says so in its own row: "this is the first
story a reader sees anything from"). So: **a landing story, not "no landing."**
