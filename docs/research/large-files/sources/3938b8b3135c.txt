Related but different: #246 (4.0.3 regression, blank-line separated containers) and #263 (closing many containers). This one is a single open container followed by many lazy continuation lines. It reproduces in 4.0.2.

Affected package

micromark@4.0.2

Steps to reproduce

import {micromark} from 'micromark'

for (const n of [1000, 2000, 4000, 8000]) {
const value = '- a\n' + 'a\n'.repeat(n) // or '> a\n' + 'a\n'.repeat(n)
const runs = [0, 1, 2].map(() => {
const start = performance.now()
micromark(value)
return performance.now() - start
})
console.log(n, Math.min(...runs).toFixed(1), 'ms')
}

Expected behavior

Time that grows linearly with the number of lines.

Actual behavior

Each doubling takes about four times as long (Node 24, fastest of 3):

n lazy lines
- a list item
> a block quote

1000
67 ms
55 ms

2000
198 ms
128 ms

4000
791 ms
764 ms

8000
3.0 s
3.3 s

For each lazy continuation line, the document tokenizer appears to scan back through every earlier event of the open paragraph to find the one that keeps the line in it. That makes n lazy lines cost O(n²). Remembering the event matched for the previous lazy line, and checking it first before falling back to the full scan, made this linear in our local experiment without changing output on a large random corpus. We didn't ship that patch, but we're happy to send a PR if that approach sounds right.
