Affected package

micromark@4.0.3

Steps to reproduce

Steps to reproduce

When a container (block quote or list) closes, lib/initialize/document.js moves the container

exits earlier with an EditMap (in continued and in closeFlow). EditMap#consume rebuilds the

entire self.events array, although the edit only touches its end (indexBeforeFlow is the last

chunkFlow exit). Every closed container therefore costs time proportional to the whole document,

so parsing is quadratic in the number of containers.

Run:

import { fromMarkdown } from "mdast-util-from-markdown";

for (const n of [2000, 8000, 32000]) {
const text = "> A quote with *emphasis*.\n\n".repeat(n);
const start = performance.now();
fromMarkdown(text);
console.log(n, Math.round(performance.now() - start), "ms");
}

Each fourfold increase in n makes parsing roughly sixteen times slower.

Actual behavior

Actual behavior

Parsing time grows quadratically with the number of closed containers. A 1 MiB document of short

block quotes takes about 107 s; a 1 MiB document of block quotes and short lists takes about 126 s.

Expected behavior

Parsing time grows linearly with the document size.

A possible fix, in both places in lib/initialize/document.js and dev/lib/initialize/document.js:

- const editMap = new EditMap()
- // Inject the exits earlier (they’re still also at the end).
- editMap.add(indexBeforeFlow + 1, 0, self.events.slice(indexBeforeExits))
- // Discard the duplicate exits.
- editMap.add(indexBeforeExits, index - indexBeforeExits, [])
- editMap.consume(self.events)
+ const exits = self.events.slice(indexBeforeExits)
+ self.events.length = indexBeforeExits
+ self.events.splice(indexBeforeFlow + 1, 0, ...exits)

With it, the 1 MiB block quote document parses in about 1.5 s, and time grows linearly. The

resulting mdast trees (with GFM) were byte-identical to the unpatched output across 135 test

documents, including nested quotes and lists, lazy continuation, and fenced code in list items.

Happy to open a PR with this change and a test if the approach works for you.
