Issue body actions

Affected packages and versions

micromark 4.0.3, with micromark-core-commonmark 2.0.4 and micromark-util-edit-map 1.0.0. micromark 4.0.2, with micromark-core-commonmark 2.0.3, isn't affected.

Steps to reproduce

import {micromark} from 'micromark'

// 32 KB of block quotes, each followed by a blank line.
const value = '> a\n\n'.repeat(6554)

console.time('micromark')
micromark(value)
console.timeEnd('micromark')

Expected behavior

Time that grows linearly with the input, as in 4.0.2, which takes 168 ms here.

Actual behavior

4.0.3 takes 3.2 s. Four times the input takes 20 to 25 times as long:

Times are for micromark(value), the fastest of 3 runs. Each section is a setext heading, two paragraphs, a block quote, and a two-item list:

const p = 'Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore.\n'
const section = (i) => `Section ${i}\n----------\n\n${p}${p}\n> ${p}\n- Item\n- Item\n\n`

Commit 90c8d3e, which added micromark-util-edit-map, moved three edits from splice to EditMap:

resolveToSetextUnderline, once per setext heading.

documentContinue, when a new list item closes containers inside the previous one.

writeToChild, when a line without > closes a block quote, such as a blank line.

Each ends in EditMap.consume, which rebuilds the whole event list, including the events before the first edit. 4.0.2 spliced near the end of the list instead, so one rebuild per heading, quote, or list item makes the total quadratic.

A possible fix, in packages/micromark-util-edit-map/dev/index.js: after the loop, events holds only the untouched prefix, so consume can keep it instead of copying it. Each call then copies only the events after the first edit, which sits near the end at these three places.

events.length = this.map[index][0]
}

- vecs.push(events.slice())
- events.length = 0
-
let slice = vecs.pop()

The table's last column shows that it restores 4.0.2's times. HTML and event offsets match unpatched 4.0.3 on 652 CommonMark spec examples, 8,711 local Markdown files, and 100,000 random inputs.

#244 rewrites consume for peak memory but still copies the whole list on every call.

Chat SDK 4.44.0's release notes tell users to keep micromark at 4.0.2 because of this. That only covers block quotes and lists. The setext heading part comes from micromark-core-commonmark 2.0.4, and micromark@4.0.2 accepts ^2.0.0, so a fresh install of 4.0.2 today gets 2.0.4 and stays slow on setext headings.
