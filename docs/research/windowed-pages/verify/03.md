# Verify 03 · node-budget

Web check (`check-corpora.mjs --web`): 66 quotations, 66 found, 0 failed, 0 warnings. The chapter says "No web sources"; its sources are the probe files. Every number below was checked against the JSON and logs in `probes/node-budget/` (read through `table.mjs`) and against `node-budget.mjs`. No browser was rerun.

What the probe does:
- "Nodes" is a `TreeWalker(SHOW_ALL)` count under the first visible `.marxy-article`, which is `nodes.articleAll` in the JSON. It includes text nodes and excludes the article root. `nodes.article` is the element count (`getElementsByTagName('*')`).
- Forced layout is timed in-page with `performance.now()` around the style write and `void a.offsetHeight`. The reported value is the median of N reps, with the minimum beside it.
- N is 9 in `run-rest.sh`. The default is 15. The WebKit prose run (`webkit-md-prose.json`) has no recorded rep count, and its launcher line is not in `run-rest.sh`.
- Key "total" is NOT timed from the capture-phase keydown listener, as NOD-01 says. `window.__stamp()` runs in a separate `page.evaluate` BEFORE `page.keyboard.press`, and `total = frame end - __t0`. The key total therefore includes the Playwright press round trip. The capture/bubble listeners only give "key sync".
- Median is `s[floor(n/2)]`, which is correct for odd N.
- "Settle" is the time `__quiet` took to see six calm 100 ms ticks, so 0.6 s is the probe's floor, not a cost.
- Open wall time is `Date.now()` around `open` plus `contentComplete`, including the Playwright round trip.

## Corrections for the lead

1. Fix the nodes-per-KB estimate (Recommendation, "What follows"). Use about 40–65 per KB for prose and about 470 per KB for dense. The mount-whole rule should then be about 150–250 KB prose and about 20 KB dense, or be expressed in nodes from the micromark tree only.
2. Fix "80 KB more" in the Options table. It is about 800 KB.
3. Fix "10–20x" in the title and abstract. The data say about 20–30x.
4. Fix the key-total description. It is stamped before the Playwright keypress, so IPC is included and the floor is not cadence alone. Say how the 11 reps and the load average of 11–22 were obtained, or drop them. The probe records neither.
5. Fix "per element 0.7 µs at 100k". It is about 1.3 µs; 0.7 µs is per node.
6. Reconcile the `:has()` range (20–40% in the title and TL;DR, 30–45% in the body). Per-node figures give 26–41%.
7. TL;DR RO "2–6 ms" should be "6–8 ms" (Chromium 8).
8. Relabel the dense layout at 10k as an extrapolation (the smallest run is 28k). Note that the 0.6 s settle is the probe floor.
9. The Windows Chromium numbers, `ro-cost.txt` and the "0.11 → 0.35 ms" append are not in the probe outputs. Mark them as reported, not measured, or move them to Open questions. The NOD-04, NOD-05 and NOD-06 titles carry `[measured]` but rely on them in part.
10. The 468k WebKit dense width change (25.6 s) is left out of NOD-05. It would support the typeset-by-distance case.
