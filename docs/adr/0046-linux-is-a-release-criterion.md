# ADR-0046 — Linux is a release criterion, not a pull-request gate

- **Status:** accepted (author, 2026-10-02)
- **Date:** 2026-10-02
- **Amends:** `docs/brief.md` and `docs/scope.md` "Platforms" ("macOS and Linux at parity" in v1),
  ADR-0016's "WebKitGTK on a Linux runner" for screenshot diffs, and ADR-0019 (the v1 cut: AppImage
  and Flatpak). Keeps D-A9 (the version-keyed weight offset).
- **Evidence:** `docs/research/audit-2026-10/10-overfit-decisions.md` §3.3.

## Context

"The reader shelf on Linux is empty" is a market observation, and a good reason to ship Linux. The
mechanism that grew around it asks for parity before the first release: a WebKitGTK weight harness,
Linux screenshot baselines for every corpus file (`fixtures/baselines/webkit-linux/`,
`fixtures/baselines/webkitgtk/`, `fixtures/baselines/rag/webkit-linux/`), a `gates` job on two
runners (`.github/workflows/ci.yml`, `os: [macos-latest, ubuntu-latest]`), and AppImage plus Flatpak
in the cut. The baselines cannot be produced on the only machine the project has
(`docs/plan/deltas/2026-09-28-stuck.md`: the Linux PNGs cannot be produced on the Mac), so stories
that need them wait for a desktop that does not exist, and every corpus addition is a cross-platform
ceremony. A Linux render nobody has looked at is not evidence of parity.

## Decision

1. **Linux builds in CI and ships as a pre-release artifact.** The `gates` job keeps building the
   Linux binary and running the tests that need no baseline (unit, golden, fidelity, no-network).
   `.github/workflows/release.yml` keeps its `x86_64-unknown-linux-gnu` target and publishes the
   AppImage and `.deb` as a pre-release, labelled as such in the release notes.
2. **Parity is a release criterion for a Linux release, verified by a person on hardware.** A
   Linux release is not cut until the author, or a reader they trust, has opened the corpus on a
   real Linux desktop (WebKitGTK) and recorded what they saw in the release notes. This replaces
   the screenshot comparison; it does not apologise for it.
3. **Linux screenshot baselines leave the pull-request path.** The Linux directories under
   `fixtures/baselines/` are not compared by `scripts/gate-aesthetics.mjs` on a PR. They may be
   regenerated by a Linux runner in the nightly workflow (ADR-0047), where a missing baseline is a
   line in a report and not a red pull request.
4. **The weight-offset token stays.** `[linux] weight_offset` in `config.toml`
   (`packages/theme/src/config.ts`, `linuxWeightOffset`) and the WebKitGTK version table are one
   line each and cost nothing when nobody is on Linux.
5. **Flatpak and its permissions (D-A34) wait for the Linux release.** Nothing in the pre-release
   needs them.
6. **Corpus additions need one engine.** Adding a file to `fixtures/corpus` regenerates the macOS
   baselines only.

## Consequences

- The two-runner `gates` matrix may collapse to one runner for the gates that need baselines; the
  Linux build stays as a compile-and-test job. That restructuring belongs to the pruned-PR-path
  story, not to this ADR.
- Stories blocked on Linux PNGs (MARXY-22, MARXY-44 in the stuck delta) stop being blocked.
- A Linux regression can merge unnoticed until the next hand check. That is the price, and it is
  bounded by the pre-release label.
- `docs/scope.md` and `docs/brief.md` say "macOS first, Linux pre-release" instead of parity.

## Rejected

- **Drop Linux.** The market observation is right and the Tauri build is nearly free.
- **Keep the Linux baselines and generate them in CI.** A CI-produced baseline nobody judged is the
  same unreviewed approval as the macOS one, on a second engine.
- **Defer the Linux build entirely.** The build is the cheap half and the one that catches compile
  breaks.

## How we would know this was wrong

1. A Linux pre-release user reports a rendering fault the macOS corpus would have shown: add a
   nightly Linux comparison, not a PR gate.
2. Nobody checks on Linux hardware for two releases: the criterion has become decoration; either
   find the person or stop calling it a release.
