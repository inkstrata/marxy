# 02 macOS integration (read-only probe of b16c76b3, 2026-11-26)

**Bottom line.** The Mac shell is more finished than "nobody has used it" suggests: a complete native menu (app, File, Edit, Format, View, Go, Window, Help) built from one data table, a Cmd-aware key layer, Apple Event opens with a cold-start queue, single-instance forwarding, an APFS-aware atomic save that carries xattrs and ACLs, and a 23 MB arm64 bundle under the 30 MB budget. Nothing found would stop the app launching. Two things matter before a tag a Mac user downloads: (1) the DMG is ad-hoc signed and not notarized, and the release note's "right-click, Open" no longer works on current macOS, so the first-run instruction is wrong (MAC-01); (2) any quit that is not the in-app Cmd+Q (Dock "Quit", Apple-event quit, logout/shutdown) exits without the dirty-document prompt (MAC-02). Everything here is from code and the installed bundle; no window was opened, so none of it is confirmed by eye.

## Findings

**MAC-01 [BLOCKER] Unsigned, un-notarized build with a first-run instruction that no longer works.**
- Evidence: `codesign -dv` on /Applications/Marxy.app: `Signature=adhoc`, `flags=0x10002(adhoc,runtime)`, `TeamIdentifier=not set`, Sealed Resources present; `codesign --verify --deep --strict` passes; `spctl --assess -vv` says `rejected`; no entitlements. `tauri.conf.json` `bundle.macOS` = `minimumSystemVersion 13.0`, `signingIdentity "-"`, no entitlements file, no hardened-runtime or notarization settings. `.github/workflows/release.yml` builds only `aarch64-apple-darwin` and its release body says "open it with right-click, Open the first time". From macOS 15 that route is gone: the user must try to open, then System Settings > Privacy & Security > Open Anyway. A downloaded DMG also carries quarantine, so Gatekeeper will block it.
- Smallest fix: if a Developer ID is not available, rewrite the release body (and any README line) to the real steps, including `xattr -dr com.apple.quarantine /Applications/Marxy.app` as the fallback. Otherwise sign and notarize. Either way, say "Apple silicon only" (MAC-12).

**MAC-02 [SHOULD, top priority] Non-menu quits skip the unsaved-changes prompt.**
- `apps/desktop/src-tauri/src/main.rs` handles `RunEvent::WindowEvent::CloseRequested` (1638) and routes menu Quit/Close through `request_close_of_main` (1470), which asks the webview first. There is no `RunEvent::ExitRequested` arm (grep: none). Dock > Quit, `osascript ... quit`, logout and shutdown send the Apple quit event, which Tauri turns into an ExitRequested that is allowed by default, so the app exits at once. The docs promise "a document with unsaved changes is never left behind" (docs/using-marxy.md:186). PR #774's installer also quits the app this way.
- Smallest fix: in the run closure add `if let RunEvent::ExitRequested { code: None, api, .. } = &event { api.prevent_exit(); request_close_of_main(app); }` (code is `Some` when `quit_now` exits, so no loop). Needs a hand check (list below).

**MAC-03 [SHOULD] Source and text group claims `LSHandlerRank = Default` for ~60 extensions and public.text/json/html/xml.**
- Info.plist (generated from `bundle.fileAssociations`, tauri.conf.json): group 2 "Source and text" is `Default`, as is Markdown. Marxy then competes with Xcode, TextEdit and browsers to be the double-click app for .json, .html, .xml, .css, .sh, and Launch Services breaks ties unpredictably. Open With will list Marxy for all of them (that part is right). Fix: group 2 `rank: "Alternate"` (tauri `fileAssociations[].rank`); keep Markdown at Default. Note group 1 (Markdown) has no `LSItemContentTypes`; `.md` resolves by extension, which works, but adding `net.daringfireball.markdown` makes Open With reliable. `.mdx`, `.term`, `.session` are extension-only. I did not dump Launch Services (the dump takes minutes), so which app Finder picks for .md today is unverified.

**MAC-04 [OK] Opening files.**
- `RunEvent::Opened` handled under `cfg(macos)` (main.rs:1661): file URLs only, to canonical absolute paths, then `deliver_open_files` (1036), which puts them in scope, raises the window, and either emits `marxy:open-files` or queues until the page calls `take_pending_opens` (cold start). Finder double-click, `open -a Marxy f.md`, and Dock-icon drop all arrive as Opened. A running app is reused by LaunchServices; `open -n` or a CLI relaunch goes through `tauri-plugin-single-instance` (1522) with `-psn_` and `-flag` args filtered (959). Window drop: `DragDrop::Drop` (1653) keeps regular files only (folders silently ignored). Tests: `absolute_document_path`, `document_paths_from_drop`, pending-queue unit tests; the Apple-event path itself has no automated test.

**MAC-05 [OK] Menus and keys.**
- Native menu from `app_menu::MENU` (main.rs:1189) with About/Services/Hide/Hide Others/Show All/Quit under "Marxy", Settings… on Cmd+, , an Edit menu with the predefined Undo/Redo/Cut/Copy/Paste/Select All (so Cmd+C/V/X/A/Z work in WKWebView fields), Window (Minimize, Zoom) and Help; menu-item tests check the menu matches the registry. `pane/keys.ts:92-106`: `Mod` = Command on a Mac, Ctrl elsewhere; Option-typed characters and AltGr are excluded. Cmd+N/O/S/F/P/W/Q are menu accelerators. Cmd+W is "Close Window" and quits the app, because Marxy is single-window (main.rs:1219 comment, keys.ts:30). A Mac user will notice that red-button/Cmd+W ends the app (MAC-10).
- Items to look at by hand: `Ctrl+\`` (Inline Code) is a literal Ctrl chord in the Format menu; Cmd+Alt+B and Cmd+\ may collide with system or input-source shortcuts.

**MAC-06 [OK, one nit] Window.** No `titleBarStyle`/`decorations` setting, so a plain native title bar with normal traffic lights; `minWidth 564, minHeight 480`, default 960x760, `resizable`. Size and position are saved in `window.json` in physical pixels and clamped to the monitors present (`window_state.rs:65-160`, tests for a missing screen and an off-screen title strip). Maximized is restored; native full-screen is not saved (a Mac user would expect to relaunch into full screen only if they quit in it). The window starts hidden with `backgroundColor #000000` and is shown in `setup` (main.rs:1566), not on first paint: in light mode that may flash black on a cold start. Light/dark: the theme layer reads `prefers-color-scheme` (look/paint.ts, theme/reader-config.ts); WKWebView follows the system. Cannot be judged headlessly.

**MAC-07 [OK with gaps] Atomic save on APFS.** `atomic_write.rs:1483-1520`: stage beside the target with `create_new`, `fs::copy` target to temp (on macOS std uses `fcopyfile(COPYFILE_ALL)`, which carries mode, ACL and xattrs, so Finder tags and `com.apple.quarantine` survive), overwrite bytes, rename over. A symlinked target is resolved and saved through the link (1032, test 1979); dangling link refused. Refused outright: read-only, hard-linked (nlink>1), non-regular, ownership change. Test `extended_attributes_survive_the_save_on_macos` (2250) and exFAT-refusal test (2622) are the macOS-only coverage; exclusive rename uses `renamex_np` (700). Gaps: the creation (birth) date is new after every save, because the file is a new inode; nothing sets it back and no test covers it. Finder "Created" will reset. [LATER, `setattrlist` ATTR_CMN_CRTIME, or state it in the docs.]

**MAC-08 [SHOULD, unverified] iCloud Drive "dataless" files.** No code or test mentions dataless/SF_DATALESS/iCloud (grep over src and tests: one unrelated ADR). Reading or saving a placeholder makes the kernel download it on first read, synchronously, on whichever thread does it; `fs::copy` in `stage` would also trigger it. A reader pointed at a Desktop/Documents folder synced with iCloud may stall the index walk or save. Smallest fix: none needed for a first tag if the owner accepts the stall; otherwise detect `st_flags & SF_DATALESS (0x40000000)` in `stat_file` and show "not downloaded". Cannot be confirmed without an iCloud placeholder.

**MAC-09 [LATER] Paths and names.** No Unicode normalization of file names on the Rust side (`rg nfc|nfd` hits only palette search, theme config and core text code), so a name typed as NFC in a link will not match an APFS-preserved NFD name by string comparison; APFS itself is normalization-insensitive for lookup, so opens work and only string equality and the recent list are at risk. Case-insensitive volumes: `write_new` refuses a case-variant of an existing name (test 2496); `keep_disk_case` is Windows-only, so saving `readme.md` over `README.md` on macOS renames the file to the spelling it was asked with. `/var -> /private/var`: `real_path` canonicalizes with `dunce::canonicalize`; tests canonicalise their temp roots (sqlite_tests.rs:13) and STATE.md records the earlier scope fix. FSEvents: `notify` 8 `RecommendedWatcher` (watch/spawn_notify.rs:12) uses FSEvents by default; watch tests exist but none are macOS-specific.

**MAC-10 [LATER] Close box quits.** Documented, deliberate (single window). A Mac user used to keeping the app open after closing the last window will notice; note it in the release text.

**MAC-11 [LATER] No Trash.** No code deletes or trashes user files (grep trash/recycle: none), so nothing to get wrong; "Move to Trash" is simply absent.

**MAC-12 [SHOULD] Apple silicon only.** `lipo -archs` = `arm64`; release matrix is aarch64 only; `LSMinimumSystemVersion 13.0`. Intel Macs cannot run it. Say so in the release text. Size: `du -sh` 23 MB (23,716 KB) against 30 MB: passes (7 MB headroom). Bundle: ID `dev.marxy.app`, version 0.1.0 (same as the first, already-shipped v0.1.0 per release.yml comment: pick a new version before tagging), 2 document-type entries, `icon.icns`, no `NSHumanReadableCopyright`.

**MAC-13 [LATER] CI on the PR head is red.** Run 45925455675 (5705e79d): macOS job `unit-desktop-browser` 44 pass, 1 fail (all other steps pass; cargo 650 pass, 6 skip). Outside my area but the release gate depends on it.

## PR #774 review (head 5705e79d, installer-macos.mjs and work.mjs)

Verdict: **merge after named fixes** (none are dangerous; one is a data-safety hole in the swap).
- Deletes, checked: `rmSync(built)` removes only the just-built bundle under the worktree's `target/` (a zip copy is kept first); `rmSync(staged|old)` touch only `<dest>/Marxy.app.installing|.previous`; the builds folder is only written to (mkdir, zip, BUILD.txt), never removed. Safe.
- `lsregister -u`: only paths whose first `identifier:` is `dev.marxy.app` and that differ from the installed copy; a mounted DMG or ~/Applications copy of Marxy is also unregistered (intended, printed). Fine. It calls `lsregister -dump` with no timeout, up to four times; my own dump took longer than 2 minutes, so expect a slow, silent step. Add a note or timeout.
- Fix before merge, **P1**: the swap is not recoverable. `installed -> .previous` then `staged -> installed`; if the second rename fails the working app sits at `.previous`, and the next run's `rmSync(old)` deletes it. Rename back in a try/catch, and delete `.previous` only after `staged` is in place.
- Fix, **P2**: `pickDest` returns /Applications when Marxy is already there even if it is not writable (an app installed by another user); `rmSync(staged)` then throws EACCES and the run stops after keeping the copy. Fall back to ~/Applications when `writable()` is false, or exit with a clear "not writable, pass --dest".
- Fix, **P3**: `quitInstalled` uses the Apple quit event; per MAC-02 that bypasses the dirty prompt until MAC-02 lands, and then SIGTERM/SIGKILL follow after 8 s. Note it, or skip the kill steps and ask the owner.
- Shim: quoting is correct (single quotes with `'\''` escaping), refuses to overwrite a file it did not write, skips when ~/.local/bin is not on PATH. Nit: an argument that starts with `-` reaches `open` as an option; add `--args`-free guard or `case` on `-*`. `open "$app"` with no args is right.
- Re-runs: staged/old are cleared first; worktree `status` guard stops on local changes; merge conflicts abort cleanly. Idempotent apart from P1.
- `checkBundle` demands "Sealed Resources" in `codesign -dv`; verified present on the installed bundle.
- Tests: `installer-macos.test.mjs` exercises the POSIX helpers (fixed in 5705e79d); the swap, quit and sweep paths have no test.

## For the owner to check by hand on the Mac
1. Double-click a .md in Finder and with Marxy not running: the file opens in a window with no empty-window flash.
2. With Marxy running, `open -a Marxy other.md` and a drop on the Dock icon open in the same window.
3. Right-click a .md and a .json in Finder: Marxy is listed in Open With; check what Get Info says is the default for .json and .html.
4. Type in a text field and a Source editor: Cmd+C, V, X, A, Z and Cmd+F behave.
5. Make an unsaved edit, then Dock icon > Quit and Apple menu > Log Out: see whether a prompt appears (MAC-02).
6. Cmd+W and the red button: confirm the app quits with the prompt when the document is dirty.
7. Launch in light and in dark appearance: look for a black flash before the first paint, and confirm the page follows System Settings.
8. Enter native full screen, quit, relaunch: note the result; resize, move to a second display, quit, relaunch.
9. Save a file that carries a Finder tag and one inside an iCloud-synced Desktop folder: the tag survives and the save does not hang on a not-downloaded file.
10. Download the DMG from the pre-release on a clean user account and follow the release note as written.
