# Notable Tauri-Based Desktop Apps (Landscape, as of 2026)

## What is listed on Tauri's own official showcase/"Apps made with Tauri" page (tauri.app)?

### Takeaway
Tauri does **not** currently maintain an official in-house showcase page on tauri.app itself; the canonical community-maintained references are the `awesome-tauri` GitHub repo and the third-party site madewithtauri.com. Any future citation of "the Tauri showcase" should point to one of these, not to a page on tauri.app.

### Cited Findings
- Tauri used to have a showcase page on their website but removed it in favor of the `awesome-tauri` repository; maintainers are "not opposed to re-introducing it at some point, but it won't happen in the foreseeable future" — [GitHub Discussion #7643](https://github.com/tauri-apps/tauri/discussions/7643)
- The current official/semi-official community resources for finding real Tauri apps are: the GitHub "Show and Tell" discussions, the `awesome-tauri` repo, madewithtauri.com (run by a Tauri working-group member), and the Tauri Discord's #showcase channel — [GitHub Discussion #7643](https://github.com/tauri-apps/tauri/discussions/7643)
- `tauri-apps/awesome-tauri` describes itself as "🚀 Awesome Tauri Apps, Plugins and Resources" and is the maintained curated list — [tauri-apps/awesome-tauri](https://github.com/tauri-apps/awesome-tauri)
- madewithtauri.com bills itself as "A curated list of awesome projects made with Tauri" where developers can submit their own project — [madewithtauri.com](https://madewithtauri.com/)

### Inferences
- Because there is no single authoritative Tauri.app showcase, individual app claims of "built with Tauri" (whether from madewithtauri.com submissions or third-party blogs) need per-app verification against the app's own repo (package.json / Cargo.toml / `@tauri-apps/cli`), not just inclusion in a list — several entries below turned out to be stale or wrong on closer check (see AFFiNE, Warp, RustDesk).
- A third-party site, tauriapp.com/apps, also claims to host a showcase of "fully-built Tauri applications" — this is not an official Tauri project property and was not independently verified for this research; treat listings there with the same per-app verification standard.

### Gaps
- Did not independently audit the full current contents of `awesome-tauri` or madewithtauri.com category-by-category; only spot-checked individual apps referenced in search results (below).

## Which well-known productivity/writing/reading/dev-tool apps use Tauri specifically? (verify each candidate individually)

### Takeaway
Genuinely verified Tauri apps relevant as case studies: **Spacedrive** (file manager), **Aptakube** (Kubernetes GUI), and **Pake** (webpage-to-desktop-app packager). Several widely-assumed or claimed candidates are **not** Tauri: Warp (custom native Rust/GPU UI), RustDesk (Flutter + legacy Sciter), Obsidian (Electron, confirmed again), and AFFiNE (migrated *away* from Tauri, now Electron). "Tabby" is ambiguous — the well-known terminal (Eugeny/tabby, tabby.sh) is Electron; a separate, much smaller/newer project also named Tabby (markbrutx/Tabby) is Tauri-based but is not the notable one.

### Cited Findings
- **Spacedrive** — open-source, cross-platform file explorer/file manager powered by a Rust "virtual distributed filesystem"; uses Tauri "to create a pure Rust native OS webview, resulting in a smaller bundle size and lower memory usage compared to traditional Electron apps," using the "PRRTT" stack (Prisma, Rust, React, TypeScript, Tauri) — [madewithtauri.com/submissions/spacedrive](https://madewithtauri.com/submissions/spacedrive), [Spacedrive docs](https://v2.spacedrive.com/overview/introduction), [openapps.pro](https://openapps.pro/apps/spacedrive). Open source repo referenced across multiple mirrors, e.g. [XiangCoder/spacedrive-File-Manager](https://github.com/XiangCoder/spacedrive-File-Manager) (the canonical repo is spacedriveapp/spacedrive on GitHub, per the project's own docs).
- **Aptakube** — a "modern, lightweight and multi-cluster Kubernetes GUI" for Windows/macOS/Linux; confirmed "built with Tauri for a fast, tiny, native experience" and built with Rust, explicitly contrasted with Electron-based alternatives — [GitHub - aptakube/aptakube](https://github.com/aptakube/aptakube), [madewithtauri.com/submissions/aptakube](https://madewithtauri.com/submissions/aptakube), [BuildWith.app listing](https://buildwith.app/apps/aptakube). It is closed-source freeware, not open source (the GitHub repo hosts the site/issue tracker, not evidence the app code itself is public — this was not independently confirmed as OSS; flagged as a gap below).
- **Pake** (`tw93/Pake`) — "Turn any webpage into a desktop app with one command"; uses Tauri/Rust as its underlying framework, explicitly marketed as "much more lightweight and faster than JS-based frameworks" because of Tauri — [GitHub - tw93/Pake](https://github.com/tw93/pake). Open source, MIT-style project.
- **Warp is NOT Tauri (and NOT Electron)**: Warp's own engineering blog states "After a very brief experiment with Electron, we quickly pivoted to building in Rust and rendering directly on the GPU using Metal (Mac's GPU API)," and that the team built its own custom Rust UI framework ("warpui"), inspired by Flutter, in partnership with Atom co-founder Nathan Sobo — [Warp: How Warp Works](https://www.warp.dev/blog/how-warp-works). **Flag:** a low-quality secondary source (lushbinary.com) was found during this research incorrectly asserting Warp is "built entirely on Tauri" — this claim is contradicted by Warp's own primary source and must not be repeated downstream.
- **RustDesk is NOT Tauri**: RustDesk's current desktop/mobile UI is Flutter (adopted across iOS/Android/Windows/Linux/Mac/Web), with a legacy Sciter-based UI kept alive only for 32-bit Windows (Flutter doesn't support it) and a separate TypeScript/JS web client — [RustDesk Wikipedia](https://en.wikipedia.org/wiki/RustDesk), [DeepWiki: User Interface](https://deepwiki.com/rustdesk/rustdesk/4-user-interface), [dev.to: RustDesk migrated from Sciter to Flutter](https://dev.to/rustdesk/rustdesk-is-migrated-from-sciter-to-flutter-279m). The team explicitly discussed and considered Tauri vs. Flutter and chose Flutter — [GitHub Discussion: Tauri or Flutter for RustDesk desktop?](https://github.com/rustdesk/rustdesk/discussions/533), [dev.to: Tauri or Flutter v3 for RustDesk app](https://dev.to/rustdesk/tauri-or-flutter-v3-for-rust-desktop-app-5dok). **Flag:** do not cite RustDesk as a Tauri example.
- **Obsidian is NOT Tauri**: reconfirmed via multiple sources that Obsidian ships as an Electron app, grouped alongside Discord, Docker Desktop, and GitHub Desktop as Electron examples — [InfoWorld: Electron vs. Tauri](https://www.infoworld.com/article/3547072/electron-vs-tauri-which-cross-platform-framework-is-for-you.html), corroborated by community discussion — [Hacker News thread](https://news.ycombinator.com/item?id=45308141). **Flag:** matches the objective's caution — Obsidian must never be cited as a Tauri example.
- **AFFiNE is NOT currently Tauri — it migrated away from Tauri to Electron.** AFFiNE's own community forum has a thread titled "Why Shift from Tauri to Electron" — [AFFiNE Community: Why Shift from Tauri to Electron](https://community.affine.pro/c/questions-answers/why-shift-from-tauri-to-electron). **Flag:** this is an important correction — some third-party "Made with Tauri" gallery aggregation results surfaced AFFiNE as a Tauri example, but that appears to reflect AFFiNE's earlier architecture before the switch; current AFFiNE desktop builds should be treated as Electron, not Tauri, unless a more recent primary source shows otherwise. The forum thread was found via search snippet only; its full content/date was not fetched in this pass — treat as a strong signal, not fully confirmed, and worth an explicit follow-up.
- **"Tabby" is two unrelated projects — do not conflate them.** The well-known, long-running terminal emulator/SSH client "Tabby" (tabby.sh, `Eugeny/tabby`, "A terminal for a more modern age") is explicitly an Electron app — its repo contains a `tabby-electron` package and an `electron-builder.yml`, and third-party coverage refers to it as "coded as an Electron app" — [Eugeny/tabby](https://github.com/eugeny/tabby), [Eugeny/tabby tabby-electron dir](https://github.com/Eugeny/tabby/tree/master/tabby-electron), [Securitron Linux blog](https://www.securitronlinux.com/arch-linux/new-tabby-terminal-coded-as-an-electron-app/). A separate, much newer and smaller project also called "Tabby" (`markbrutx/Tabby`, described as "Free, open-source macOS terminal workspace") is built with Tauri v2 + React 18 + TypeScript + Zustand + Tailwind CSS v4 — [markbrutx/Tabby](https://github.com/markbrutx/Tabby). **Flag:** downstream research must specify which "Tabby" it means; the notable/widely-used one is the Electron one.
- **RustDesk "Server Program"** — one low-quality secondary source (a 2026 SEO-style roundup) asserted a "RustDesk Server Program... built with Tauri," but this was not corroborated by any primary RustDesk source and conflicts with RustDesk's own documented Flutter/Sciter architecture above — flagged as unverified/likely incorrect, do not cite.

### Inferences
- The Tauri ecosystem's genuinely notable, verifiable production apps skew toward **dev-tool utilities** (Kubernetes GUI, webpage packagers, file managers) rather than mainstream consumer writing/reading apps — the well-known "flagship" consumer apps often assumed to be Tauri (Obsidian, Warp, RustDesk, AFFiNE) are, on individual verification, actually Electron, custom-native, Flutter, or migrated away from Tauri. This suggests downstream research should lean on the smaller, less mainstream apps (Spacedrive, Aptakube, Pake, and the long-tail markdown-editor projects below) rather than assuming any famous app is a Tauri example without a repo-level check.
- Marketing/aggregator sites (madewithtauri.com submissions, "openalternative.co", SEO round-up blogs) are self-reported or lightly-curated and can be stale (AFFiNE) or simply wrong (Warp, RustDesk-server claim) — every candidate should be checked against a primary source (the project's own GitHub repo config files, or an explicit maintainer statement) before being used as a case study.

### Gaps
- Aptakube's actual source-availability (open source vs. closed-source freeware) was not conclusively confirmed; its GitHub repo may just host issues/docs rather than the app source. Downstream research citing Aptakube as an "open source" example should verify licensing directly on the repo first.
- The AFFiNE "shift from Tauri to Electron" finding is based on a forum thread title/snippet only; the full thread, date, and whether any AFFiNE build (e.g., a mobile or web target) still uses Tauri were not fetched. Treat as strongly indicative but confirm with a direct read of the thread before citing a specific version/date.
- Did not verify Clash Verge, Bitwarden desktop, or other frequently-rumored Tauri candidates that surfaced only in unrelated search snippets — not enough signal to include or exclude them here; would need targeted follow-up searches.

## Are there any markdown viewers/editors or "reader" style apps built in Tauri specifically (not just any text editor)?

### Takeaway
Yes — there is a real, active long-tail of small/indie Tauri-based markdown editors and viewers (2024-2026), but none of them appear to be widely-known, mainstream products; most are solo-developer or early-stage open-source projects, several explicitly positioning themselves as lighter alternatives to Typora. None found so far is a pure "reader" in Marxy's specific sense (byte-preserving, non-editing, typeset-focused); most are WYSIWYG editors.

### Cited Findings
- **Markup** (`oratis/Markup`) — described as "a fast, native, open-source Markdown editor for macOS — read your Markdown like a web page, edit on demand," built on "Tauri 2, vault + backlinks + full-text search" — [GitHub - oratis/Markup](https://github.com/oratis/Markup). Notably close in spirit to a "reader-first" markdown app (read like a webpage, edit on demand) — worth flagging as the closest analog found to Marxy's positioning.
- **markdown-reader / "md-read"** (`KajiMaster/markdown-reader`) — "lightweight cross-platform Markdown viewer/editor (Tauri v2 + Milkdown)" — [GitHub - KajiMaster/markdown-reader](https://github.com/KajiMaster/markdown-reader).
- **Marko** (`SeanPedersen/Marko`) — "Tauri WYSIWYG Markdown Editor," described elsewhere as free/open-source for Windows, macOS, Linux — [GitHub - SeanPedersen/Marko](https://github.com/SeanPedersen/Marko).
- **MarkditorApp** (`greyovo/MarkditorApp`) — "Yet another WYSIWYG Markdown editor written in TypeScript and Tauri," explicit early-stage/WIP, aiming to be an open-source alternative to Typora — [GitHub - greyovo/MarkditorApp](https://github.com/greyovo/MarkditorApp).
- **markdown_tauri** (`prateekjain24/markdown_tauri`) — "A focused markdown editor built with Tauri 2.0 - gets out of your way" — [GitHub - prateekjain24/markdown_tauri](https://github.com/prateekjain24/markdown_tauri).
- **tauri-markdown** (`jeeinn/tauri-markdown`) — "A simple local markdown tool, use Tauri & Vditor & Vue3" — [GitHub - jeeinn/tauri-markdown](https://github.com/jeeinn/tauri-markdown).
- A DEV Community blog post by an independent developer, "I got tired of heavyweight Markdown editors, so I built one in Rust + Tauri that doesn't ship a browser," is a first-person account of building a Tauri markdown editor specifically to avoid Electron/Chromium bundling — directly relevant to Marxy's own rationale — [dev.to: heavyweight Markdown editors post](https://dev.to/shinya_saita/i-got-tired-of-heavyweight-markdown-editors-so-i-built-one-in-rust-tauri-that-doesnt-ship-a-4jf6). This is an opinion/build-log piece, not independently verified beyond the author's own claims.
- Also surfaced but not yet vetted: "Bokuchi," described in aggregator search-summary text as "a markdown editor built with Tauri v2 + Rust + React that renders through the OS's native WebView instead of bundling a whole Chromium instance" — this description appeared only inside a synthesized search summary, not a fetched primary source, so treat as unverified pending a direct repo check.
- A separate, unrelated find: "Typst Studio," referenced in a DEV Community post title "Typst Studio Desktop: 90% smaller, 100% native, same WASM codebase with Tauri" — suggests another Tauri-based document/typesetting-adjacent tool, but this was only seen as a search-result title and not fetched/verified — [dev.to: Typst Studio post](https://dev.to/rerere_l_f165d08cdc06148/typst-studio-desktop-90-smaller-100-native-same-wasm-codebase-with-tauri-3len).

### Inferences
- The markdown-editor niche within Tauri is populated almost entirely by small, single-maintainer or very-early-stage open-source projects rather than any breakout product — none of these have the community size, funding, or track record of Obsidian/Typora/Marked 2. This means Marxy's aesthetic/UX case studies for a Tauri-based reader should probably draw more from Tauri's general architecture patterns (Spacedrive's use of a Rust daemon, Aptakube's native-webview approach) than from any existing markdown-specific Tauri app, since none is mature enough to be a strong design precedent.
- `oratis/Markup`'s framing ("read your Markdown like a web page, edit on demand") is the single closest positioning match to Marxy's "reader first, editing is transformation" philosophy found in this research pass, and is worth a deeper look (UI screenshots, architecture writeup) in follow-up research if the project has any design rationale posted.

### Gaps
- None of the markdown-editor candidates above were confirmed to have blog posts, GitHub Discussions, or writeups specifically about UI/UX decisions, performance, or architecture (beyond the one dev.to build-log post cited). A dedicated follow-up pass fetching each repo's README and any linked blog/Discussion would be needed to answer the "writeups about UI/UX decisions" part of the objective in depth.
- Did not verify repo activity level (stars, last-commit date, whether abandoned) for any of the small markdown-editor projects — before citing any of them as a "case study," downstream research should check they are still maintained as of 2026, since several read as early/WIP.
- `oratis/Markup`'s and `Bokuchi`'s Tauri usage were not independently confirmed by directly opening their `package.json`/`Cargo.toml` or repo — confirmed only via GitHub repo description text in search results. Recommend a direct repo check before treating them as fully verified.
