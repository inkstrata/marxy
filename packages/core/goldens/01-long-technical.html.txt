<h1 data-marxy-s="0" data-marxy-e="18">Stack evaluation</h1>
<p data-marxy-s="20" data-marxy-e="88"><strong data-marxy-s="20" data-marxy-e="31">Status:</strong> <strong data-marxy-s="32" data-marxy-e="56">OPEN — not decided</strong> · <strong data-marxy-s="60" data-marxy-e="77">Last updated:</strong> 2026-09-17</p>
<p data-marxy-s="90" data-marxy-e="308">Three weighted passes, one reversal, one user override, and a scope change
that moved the numbers a third time. All of it is recorded because a
decision log that keeps only the winning argument cannot be audited later.</p>
<p data-marxy-s="310" data-marxy-e="641"><strong data-marxy-s="310" data-marxy-e="346">The question is explicitly open.</strong> Pass 3 puts Tauri ahead by 15 points,
which now agrees with the stated lean rather than contradicting it — but
that margin comes from weights that are judgements, and the three passes
disagree with each other. The framework near the end of this document is
more useful than any of the totals.</p>
<hr data-marxy-s="643" data-marxy-e="646" />
<h2 data-marxy-s="648" data-marxy-e="657">Method</h2>
<p data-marxy-s="659" data-marxy-e="807">Metrics weighted to sum to 100, candidates scored 1–5 per metric,
weighted total normalised out of 100 (a perfect score being 5 across the
board).</p>
<p data-marxy-s="809" data-marxy-e="1139">The important property of this method, discovered rather than designed:
<strong data-marxy-s="881" data-marxy-e="936">the weights decide the outcome, not the candidates.</strong> The weights encode
judgements about priorities, so the exercise is really a way of making
those judgements explicit and arguable. If the brief changes, the scores
must be recomputed rather than assumed.</p>

<h3 data-marxy-s="3354" data-marxy-e="3373">Why it reversed</h3>
<p data-marxy-s="3375" data-marxy-e="3432">Three specific additions, each independently significant:</p>
<ol data-marxy-s="3434" data-marxy-e="4423">
<li data-marxy-s="3434" data-marxy-e="3962"><strong data-marxy-s="3437" data-marxy-e="3464">Linux became mandatory.</strong> Under Tauri that means WebKitGTK, which has
an open defect rasterizing text ~100 weight units heavier than specified
(<code data-marxy-s="3588" data-marxy-e="3612">tauri-apps/tauri#14286</code>), and whose usual remedy is a macOS-only CSS
property. For an application whose thesis is typographic quality, on a
platform now promised, this is close to disqualifying. It is why the
first metric’s Tauri score dropped from 4 to 2 — the metric changed from
measuring the <em data-marxy-s="3899" data-marxy-e="3908">ceiling</em> to measuring the <em data-marxy-s="3926" data-marxy-e="3961">floor across shipped
platforms</em>.</li>
<li data-marxy-s="3963" data-marxy-e="4217"><strong data-marxy-s="3966" data-marxy-e="4004">Live-render editing entered scope.</strong> <code data-marxy-s="4005" data-marxy-e="4022">contenteditable</code>, <code data-marxy-s="4024" data-marxy-e="4035">Selection</code>,
<code data-marxy-s="4039" data-marxy-e="4046">Range</code> and IME composition are the most engine-divergent surfaces on
the web platform, and Compose mode sits on all four. One engine
everywhere is worth a great deal here.</li>
<li data-marxy-s="4218" data-marxy-e="4423"><strong data-marxy-s="4221" data-marxy-e="4251">User CSS became a feature.</strong> Engine inconsistency stopped being only
the maintainer’s problem and became the theme authors’ problem, on an
engine whose version ships with the user’s distribution.</li>
</ol>
<p data-marxy-s="4425" data-marxy-e="4521">Remove any one and the gap narrows sharply. Remove Linux and editing both,
and Tauri wins again.</p>
<p data-marxy-s="4523" data-marxy-e="4700">Swift’s collapse is simpler: first-class user CSS requires a real CSS
engine, and Linux support is impossible for a macOS-native toolkit. Ruled
out rather than merely outscored.</p>
<hr data-marxy-s="4702" data-marxy-e="4705" />
<h2 data-marxy-s="4709" data-marxy-e="4734">Pass 3 — pared brief</h2>
<p data-marxy-s="4736" data-marxy-e="4861">Brief v3 changed the inputs materially in both directions, which is why
this pass exists rather than an annotation on Pass 2.</p>
<p data-marxy-s="4863" data-marxy-e="5248"><strong data-marxy-s="4863" data-marxy-e="4875">Removed:</strong> Typora-style live-render editing. This deletes an entire
metric — the one on which Electron scored 5 and Tauri 3 — along with the
<code data-marxy-s="5010" data-marxy-e="5027">contenteditable</code>, <code data-marxy-s="5029" data-marxy-e="5040">Selection</code>, <code data-marxy-s="5042" data-marxy-e="5049">Range</code> and IME divergence that justified
it. Editing is now plain text in CodeMirror plus source transformations
(<code data-marxy-s="5157" data-marxy-e="5175">05-view-modes.md</code>, <code data-marxy-s="5177" data-marxy-e="5204">18-document-operations.md</code>), which is uncontroversial
on every engine.</p>
<p data-marxy-s="5250" data-marxy-e="5602"><strong data-marxy-s="5250" data-marxy-e="5260">Added:</strong> a fast indexed document opener with instant switching, file
watching over indexed roots, and code observation as a first-class use
case (<code data-marxy-s="5398" data-marxy-e="5426">19-navigation-and-index.md</code>). These are Rust’s strongest suit —
<code data-marxy-s="5465" data-marxy-e="5473">nucleo</code>, <code data-marxy-s="5475" data-marxy-e="5484">tantivy</code>, <code data-marxy-s="5486" data-marxy-e="5494">notify</code>, <code data-marxy-s="5496" data-marxy-e="5504">ignore</code>, <code data-marxy-s="5506" data-marxy-e="5519">tree-sitter</code> — and they turn
startup and footprint from qualities into stated product claims.</p>
<p data-marxy-s="5604" data-marxy-e="5793"><strong data-marxy-s="5604" data-marxy-e="5617">Softened:</strong> the Linux typography gap, judged solvable rather than
disqualifying. This is a user judgement, and it happens to be the single
most consequential number in the whole exercise.</p>

<h3 data-marxy-s="6320" data-marxy-e="6344">Why it reversed back</h3>
<p data-marxy-s="6346" data-marxy-e="6422">Not because anything was learned about the frameworks. Three inputs
changed:</p>
<ol data-marxy-s="6424" data-marxy-e="7021">
<li data-marxy-s="6424" data-marxy-e="6604"><strong data-marxy-s="6427" data-marxy-e="6461">Live-render editing left scope</strong>, deleting Electron’s strongest
remaining metric. Plain-text CodeMirror works everywhere; a decorated
<code data-marxy-s="6569" data-marxy-e="6586">contenteditable</code> surface does not.</li>
<li data-marxy-s="6605" data-marxy-e="6858"><strong data-marxy-s="6608" data-marxy-e="6647">Speed and footprint became promises</strong>, not preferences. “A very fast
document opener” as a headline claim justifies a much higher weight
than the 15 it carried in Pass 1 — and this is the axis where the gap
is largest and best evidenced.</li>
<li data-marxy-s="6859" data-marxy-e="7021"><strong data-marxy-s="6862" data-marxy-e="6901">Indexing and watching entered scope</strong>, and this is the first
requirement where Rust is <em data-marxy-s="6954" data-marxy-e="6965">genuinely</em> the better tool rather than
merely a defensible one.</li>
</ol>
<p data-marxy-s="7023" data-marxy-e="7225">The Linux weight drop from 15 to 8 also matters, and it should be flagged
as the softest input in the model: it rests on a judgement that the
WebKitGTK font-weight defect is solvable, which is untested.</p>
<p data-marxy-s="7227" data-marxy-e="7499"><strong data-marxy-s="7227" data-marxy-e="7270">The honest summary of all three passes:</strong> the framework never changed,
the brief did, and each time the brief changed the answer changed with it.
That is a property of the method working, but it is also a warning that a
fourth brief revision would move the answer again.</p>
<hr data-marxy-s="7501" data-marxy-e="7504" />
<h2 data-marxy-s="7506" data-marxy-e="7534">Where the question stands</h2>
<p data-marxy-s="7536" data-marxy-e="7830">The stated lean is <em data-marxy-s="7555" data-marxy-e="7594">“swift is out, leaning toward tauri,”</em> and the user has
since confirmed the question remains open. Pass 3 now supports the lean
rather than contradicting it, which is a meaningfully different situation
from Pass 2 — the direction and the analysis agree for the first time.</p>
<p data-marxy-s="7832" data-marxy-e="7892">The reasons for Tauri that are real regardless of weighting:</p>
<ul data-marxy-s="7894" data-marxy-e="8454">
<li data-marxy-s="7894" data-marxy-e="7962">Roughly 19 MB against 190 MB for a comparable markdown application</li>
<li data-marxy-s="7963" data-marxy-e="8020">Idle memory of roughly 42–109 MB against 128–186 MB</li>
<li data-marxy-s="8021" data-marxy-e="8147">Rust’s indexing, matching and watching crates — the one place where the
better tool is not merely defensible but obvious</li>
<li data-marxy-s="8148" data-marxy-e="8231">A footprint that fits a lean open-source ethos far better than shipping
a browser</li>
<li data-marxy-s="8232" data-marxy-e="8338">A declarative capability and CSP model that aligns with the security
posture in <code data-marxy-s="8314" data-marxy-e="8338">09-theming-contract.md</code></li>
<li data-marxy-s="8339" data-marxy-e="8454">A Rust core that naturally produces the separable parse-and-render
library the publishing-platform ambition wants</li>
</ul>
<p data-marxy-s="8456" data-marxy-e="8704"><strong data-marxy-s="8456" data-marxy-e="8506">Startup is deliberately absent from that list.</strong> Most sources put Tauri
far ahead, but they compare different applications; the one source that
built the <em data-marxy-s="8612" data-marxy-e="8618">same</em> application found Electron faster. It is a reason to
measure, not a reason to choose.</p>
<p data-marxy-s="8706" data-marxy-e="8921">The weights are judgements, not facts. Weighting footprint at 10 rather
than 25 was a choice, and someone building a lean open-source tool for
people who care about such things could reasonably weight it far higher.</p>

<p data-marxy-s="11482" data-marxy-e="11768"><strong data-marxy-s="11482" data-marxy-e="11545">Revisit the direction if two or more of 1, 2, 6 and 7 fail.</strong> Note the

<h3 data-marxy-s="11770" data-marxy-e="11801">What makes revisiting cheap</h3>
<p data-marxy-s="11803" data-marxy-e="12194">The frontend is portable between Tauri and Electron — same framework, same
CSS, same libraries. Only the privileged-operation boundary differs.
Keeping file access, watching, and dialogs behind a <strong data-marxy-s="12001" data-marxy-e="12033">thin, well-defined
interface</strong> — a handful of functions, not scattered <code data-marxy-s="12076" data-marxy-e="12086">invoke()</code> calls — makes
a later switch a matter of reimplementing that interface. Worth doing
regardless of intent.</p>
<hr data-marxy-s="12196" data-marxy-e="12199" />
<h2 data-marxy-s="12201" data-marxy-e="12231">How to actually settle this</h2>
<p data-marxy-s="12233" data-marxy-e="12498">The question has now survived three weighted analyses without closing,
which is evidence that <strong data-marxy-s="12327" data-marxy-e="12363">more analysis will not close it.</strong> The weights
decide the outcome, the weights are judgements, and the brief keeps
changing. A fourth pass would produce a fourth number.</p>
<p data-marxy-s="12500" data-marxy-e="12639">What would close it is a small amount of code. Two or three days, and it
answers the load-bearing hypotheses directly rather than by proxy.</p>
<h3 data-marxy-s="12641" data-marxy-e="12654">The spike</h3>
<p data-marxy-s="12656" data-marxy-e="12719">Build the same throwaway shell twice, in Tauri and in Electron:</p>
<ol data-marxy-s="12721" data-marxy-e="13131">
<li data-marxy-s="12721" data-marxy-e="12790">Open a markdown file passed as an argument, render it, no styling.</li>
<li data-marxy-s="12791" data-marxy-e="12901">Set one paragraph with <code data-marxy-s="12817" data-marxy-e="12825">justif</code> and screenshot it on macOS and on a real
Linux distribution’s WebKitGTK.</li>
<li data-marxy-s="12902" data-marxy-e="12969">Open a large file in CodeMirror 6 in plain-text mode; scroll it.</li>
<li data-marxy-s="12970" data-marxy-e="13064">Index a few thousand files, then fuzzy-search them with a keystroke
latency measurement.</li>
<li data-marxy-s="13065" data-marxy-e="13131">Measure cold start and warm start on the actual target machine.</li>
</ol>
<p data-marxy-s="13133" data-marxy-e="13464">Steps 2 and 5 are the whole exercise. Step 2 answers hypotheses 1 and 2 —
whether the WebKitGTK weight defect is compensable, which is the only real
argument against Tauri now that editing has left scope. Step 5 answers
hypothesis 7, and it matters because the one same-application benchmark in
existence found Electron <em data-marxy-s="13455" data-marxy-e="13463">faster</em>.</p>

<h3 data-marxy-s="14587" data-marxy-e="14626">What to do regardless of the answer</h3>
<p data-marxy-s="14628" data-marxy-e="14727">Because the frontend is portable between the two, most of the work is not
blocked on this decision:</p>
<ul data-marxy-s="14729" data-marxy-e="15036">
<li data-marxy-s="14729" data-marxy-e="14841">The typesetting path, the theme contract, and the operations catalogue

<li data-marxy-s="14842" data-marxy-e="14905">The privileged-operation interface should be thin either way.</li>
<li data-marxy-s="14906" data-marxy-e="15036">The parse-and-render pipeline should be a library with no dependency on
the shell, which the publishing ambition wants anyway.</li>
</ul>
<p data-marxy-s="15038" data-marxy-e="15326"><strong data-marxy-s="15038" data-marxy-e="15088">So the stack question does not block starting.</strong> It blocks distribution
and it blocks the speed claims, but the reading experience — the part that
is actually hard and actually differentiating — can be built before the
answer arrives. That is the most useful thing in this document.</p>
